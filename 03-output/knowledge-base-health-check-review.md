# Knowledge Base ヘルスチェック設計・小規模試行

- 確認日: 2026-10-17
- 状態: Draft・試行済み（継続観測は未実施）
- 目的: Knowledge Baseの状態を振り返り、人が次に確認する領域を選ぶ。
- 想定読者: Knowledge Baseを記録・参照する人

## CIとの役割分担

品質CIは構造的な違反で失敗する。ヘルスチェックは既存判定の結果と未計測の領域を示す非ブロッキングな振り返りであり、件数を品質・成長の合否や点数にしない。自動修正・統合・削除・状態遷移は行わない。CIジョブや既存の判定基準は変更しない。

[集計スクリプト](../scripts/report-knowledge-health.mjs)は[品質検査](../scripts/check-knowledge-quality.mjs)の公開関数 `analyzeKnowledgeQuality` を再利用し、違反・候補の判定を複製しない。集計成功は違反の有無によらず終了0、読込等の失敗は終了2として未計測にする。失敗時に0件を補わない。

## 指標の定義

| 指標 | 範囲・算出方法・単位 | 機械と人の確認 | 限界 |
|---|---|---|---|
| Knowledge / Materials / Output件数 | 各層の追跡済み `.md` 数と、そのうちREADME・inbox・promptsを除いた内容メモ数。単位はファイル | 機械集計、人が用途と対象範囲を確認 | 文書量・品質・利用価値ではない。未追跡入力を含まない |
| 未確認・stale・deprecated | 02の明示状態を、採用された定義別に数え、状態不明数と分母も併記する設計 | 機械は明示値のみ集計、人が状態の意味・適用範囲を確認 | 現状は状態規約が未確定なので未計測。自由記述の単語数や確認日の古さから状態を推定しない |
| broken links | 既存解析の「出典リンク切れ」出力件数。違反総数とは分ける | 機械判定、人が対象リンクと修正方針を確認 | 対応する相対リンク・アンカーの範囲のみ。外部到達性・内容の正しさは保証しない |
| orphan | 既存解析の `orphan knowledge` 出力件数 | 機械が候補化、人が用途・参照意図を判断 | 確認日・出典のある内容メモが対象。02/03は索引からの被リンクも算入、04は内容メモからの参照で判断。被リンクなしは不要の意味ではない |
| 重複候補 | 既存解析の「重複」出力件数。同一H1/外部URLの一致グループ | 機械が一致を提示、人が双方の本文・出典を照合 | 文書数・一意な組数ではない。同じ組が別根拠で出ることもある。意味的類似を網羅しない |
| 矛盾候補 | 既存解析の「矛盾するナレッジ」出力件数。同一URLで状態記述が異なる候補 | 機械が状態差を提示、人が時点・条件・対象箇所を照合 | 状態差だけでは意味的な矛盾を確定できない |
| 昇格遅延候補 | Materials/Observationごとの準備完了記録、Knowledge対応先、待ち始めた日、合意した確認契機がある範囲で候補を列挙 | 記録の有無・経過は機械、人が昇格要否・遅れを判断 | 対応や準備状態がない資料を古さだけで未処理としない。現状は未計測、閾値を新設しない |
| 利用状況・長期間未利用 | 利用イベントの対象期間・対象範囲・欠測を示し、知識ごとの最終利用を集計する設計 | 機械集計、人が計測範囲を解釈 | 利用ログを入力していないため未計測。リンク数は使う場合も代理指標であり実利用ではない |
| 増減・推移 | 同じ指標定義・除外範囲・コード版・入力条件のスナップショット間の差 | 機械集計、人が比較可能性を確認 | 比較可能な過去入力を再取得していないため未計測。履歴のない期間を推定しない |
| 候補精度・人の作業量 | 候補の採否と根拠、独立に人が見つけた非候補例、確認開始から判断記録までの時間 | 人が記録し機械集計 | 候補0件から適合率・再現率・確認時間0を導かない。今回は未計測 |
