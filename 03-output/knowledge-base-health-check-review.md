# Knowledge Base ヘルスチェック設計・小規模試行

- 確認日: 2026-10-10
- 状態: 試行レポート
- 目的: Knowledge Base の状態と推移を振り返り、人が次に確認する領域を選ぶための非ブロッキングなレポートを設計する。
- 想定読者: Knowledge Base を記録・参照する人

## 要点

ヘルスチェックは品質CIの機械的な合否判定を繰り返さず、確認できる件数・候補と、未計測・人の確認が必要な範囲を同じレポートに示す。件数は品質や成長の点数にせず、確認作業の入口として扱う。

2026-10-10に追跡済みデータを対象に小規模試行した。Knowledge の本文メモは0件、Materials は1件、Output は3件だった。添付版とリポジトリ版の Knowledge Quality 検査はいずれも違反なし、候補出力なし、外部URL確認箇所1件だった。本文メモが少なく、候補も出なかったため、重複・矛盾・孤立の実例に基づく精度評価はできない。

## CIとの役割分担

| 領域 | Knowledge Quality CI | ヘルスチェック |
|---|---|---|
| 確定的な形式・構造違反 | リンク切れ、必須メタデータ、Markdown/リンクlintを判定し、違反時はCIを失敗させる | CI結果を再利用して件数・内訳・確認先を表示する。別の判定ロジックを実装しない |
| 人が判断する候補 | orphan、同一URLまたは同一H1の重複候補、同一URLで状態記述が異なる矛盾候補を提示する。候補だけではCIを失敗させない | 候補の発生数と参照先を示す。関係の確定、修正、削除、統合は行わない |
| 鮮度・利用・推移 | 現行検査の対象外 | 利用可能な記録・スナップショットがある場合に限り集計する。根拠がなければ未計測とする |

ヘルスチェックの実行失敗や候補件数をKnowledge Quality CIの合否条件へ追加しない。出力先は毎回保存を前提にせず、保存する場合は `03-output/` の成果物配置ルールに従い、日付・対象範囲・入力時点を記録する。

## 指標の定義

| 指標 | 対象範囲・算出方法 | 判定主体 | 限界・扱い |
|---|---|---|---|
| Knowledge / Materials / Output の件数 | 追跡済みMarkdownから索引README、inbox、promptsを除いた本文メモ数を層ごとに数える。今回の結果は Knowledge 0、Materials 1、Output 3 | 機械集計 | ファイル数であり、内容の充実度・正確さ・価値を表さない。ローカルだけにある未追跡資料は含まない |
| 未確認・stale・deprecated の知識 | 各ラベルの定義と記録規則が確立している場合のみ、その状態の記録を数える | 状態・定義の一致は人が確認 | 現在は統一された状態メタデータがない。自由記述やラベル候補を状態数として扱わない。今回の件数は未計測 |
| broken links | Knowledge Quality CI の違反出力を再利用する。今回の違反総数は0件 | 機械判定 | 到達可能性や外部URLの有効性を保証しない。外部URLは今回1箇所が確認対象として列挙された |
| orphan | CIが出す孤立候補を再利用する。今回の候補出力なし | 事実は機械、人の要確認かは人 | 被リンクがない事実だけでは不要とは限らない。用途・意図の判断が必要 |
| 重複候補 | 同一外部URLまたは同一H1のCI候補を再利用する。今回の候補出力なし | 一致は機械、重複の確定は人 | 同じ参照先・見出しでも内容が重複するとは限らず、意味的類似は網羅しない |
| 矛盾候補 | 同一URLを参照し状態記述が異なるCI候補を再利用する。今回の候補出力なし | 状態差は機械、矛盾の確定は人 | 適用条件・時点の違いで両立する場合がある。本文と出典の照合が必要 |
| 昇格の遅れ候補 | MaterialsまたはObservationからKnowledgeへの対応・準備状態が記録された場合に、その記録に基づいて確認対象を列挙する | 人が候補を確認 | 対応や準備状態が記録されていない資料を、古さだけで未処理と断定しない。今回の状態は未計測 |
| 利用状況 | 利用イベントまたはアクセス記録が存在する場合に限り、その記録の対象期間・対象範囲を集計する | 機械集計、人が解釈 | 利用記録がない場合「長期間利用されていない知識」は実測できない。リンク数を示す場合も利用実績ではなく代理指標と明記する。今回未計測 |
| 増減 | 同一定義・同一対象範囲の過去スナップショットと今回値を比較する | 機械集計、人が比較可能性を確認 | 過去スナップショットがないため今回は初回計測。増減は算出・推定しない |

## 鮮度情報の取り込み

添付資料 `knowledge-freshness-review-pr20.md`（PR #20、未マージの提案）は、知識の種類や変化要因に応じた再確認を提案している。これは確定済みの共通メタデータではないため、今回のレポートで `stale` 等の状態を自動生成しない。確認日だけで失効させず、将来、再確認契機が本文に記録されている場合は候補と根拠を示し、人が適用範囲と出典を確認する。状態形式の採用は実例と運用負担を観測してから判断する。

## 関係候補の取り込み

[関係定義・確認手順（PR #16でマージ済み）](../agents/skills/filter-related-knowledge/SKILL.md)では、`duplicate`、`related`、`contradicts`、`supersedes` の意味と根拠記録を定義している。CIの一致は候補の根拠として提示し、関係の確定は人が両方の対象箇所、出典、適用条件、確認日を照合した後に行う。確定できない場合は確定リンクを追加しない。

[Knowledgeライフサイクル（PR #16でマージ済み）](../agents/skills/knowledge-lifecycle/SKILL.md)に従い、`supersedes` を確認しても旧記録を削除せず、旧情報の有効範囲と置き換え理由を追えるようにする。PR #22の更新タスク記録は、現行データで候補がないこと、実データ精度・見逃し・確認時間が未測定であることを記録している。今回の試行でも候補はなく、この未評価範囲は解消していない。

## 2026-10-10 小規模試行

### 範囲と方法

- 対象: `git ls-files` が返す追跡済みファイル。CIスクリプトが除外する `01-secret/`、`06-storage/`、`99-trash/`、`.takt/` は解析対象外。
- 件数: 追跡済みMarkdownから各層のREADME、`inbox/`、`prompts/` を除いて数えた。Knowledge 0件、Materials 1件、Output 3件。
- 品質検査: 添付された `check-knowledge-quality.mjs` と `scripts/check-knowledge-quality.mjs` の両方を実行。どちらも終了status 0、「違反なし」、候補出力なし、外部URL確認箇所1件。
- 過去比較: 同じ定義の履歴スナップショットは今回の入力・確認範囲で得られず、今回を初回計測とした。増減は未計測。

### 結果と解釈

Knowledge本文メモが0件のため、この試行のKnowledge層の構成・鮮度・関係候補は評価できない。Materials 1件、Output 3件という値もファイル数であり、健全性の合否や成長の評価には使わない。CIの違反・候補が0件だったことは、現在の追跡データに対する当該検査の結果であり、意味的な重複・矛盾がないことや、Knowledge全体が健全であることを示さない。外部URL確認箇所1件も、リンク先の内容・到達性を確認した結果ではない。

利用記録・アクセス計測は今回の対象資料から確認できず、利用状況は未計測である。リンク数を利用実績の代用にはしていない。`stale` / `deprecated` 等の統一状態もないため、これらの件数は未計測であり、0件とは扱わない。昇格準備状態とObservationの対応記録も確認できず、昇格遅延候補は未計測である。

### 次に人が確認する領域

1. Knowledge本文メモが追加された後、鮮度の再確認契機、適用条件、出典が記録されているかを少数の実例で確認する。
2. CI候補が出た場合、候補ごとの採否・関係・双方の対象箇所と根拠を記録し、実データの適合率を評価する。人が独立に見つけた非候補例も記録して見逃しを確認する。
3. 再確認や候補確認の開始から判断記録までの時間と対象数を記録し、人の作業量を評価する。
4. 過去スナップショットが得られた時点で、定義・範囲の同一性を確認してから比較する。履歴がない期間の増減は推定しない。
5. 利用イベントを計測する運用が導入された場合、その対象範囲・期間・欠測を明示した上で利用状況を集計する。それまでは未計測とする。

## 未反映分・限界

- PR #16の関係定義とライフサイクル資料は、依頼文の説明に従いmainへマージ済みの成果として参照した。今回、これらの既存資料は変更していない。
- PR #20の鮮度レビューは未マージの提案であり、mainの確定仕様として扱っていない。状態メタデータの導入・一括移行も行っていない。
- PR #22のタスク記録には実データ評価の未完了が残る。今回も候補が出なかったため、適合率、再現率、意味的な見逃し、実際の確認時間は算出できない。
- 現在の対象ではKnowledge本文メモがなく、利用記録・過去スナップショット・昇格準備記録も確認できない。各項目を推定値で補っていない。
- この試行は追跡済みMarkdownと既存CI出力に限られ、未追跡データ、知識の意味的妥当性、実利用状況を評価していない。
