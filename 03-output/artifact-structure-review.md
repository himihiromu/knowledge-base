# タスク成果物の配置・構造ルール調査提案（初回案）

- 状態: 提案・未確定
- 目的: 成果物の役割と配置の適合状況を整理し、配置・リンク規約の判断材料を提示する
- 想定読者: 本リポジトリの利用者とルールを確定するユーザー
- 根拠: task添付の [artifact-structure-rules.md](../05-todo/tasks/artifact-structure-rules.md)、[workflow.md](../00-rules/workflow.md)、[repository-readme.md](../README.md)、[output-readme.md](README.md)、[todo-readme.md](../05-todo/README.md)、[skills-readme.md](../agents/skills/README.md)、[scripts-readme.md](../scripts/README.md)。リンク先はorderのファイル対応表にある元パスを使い、相対リンク80件の存在を確認した。`artifact-inventory.txt` は実行時スナップショットのため、恒久リンクにしていない。

## 確認できた既存ルール

- `00-rules` は全体ルールとテンプレート、`02-knowledge` は整理・検証済み知識、`03-output` は目的に応じた成果物、`04-materials` は元資料・未整理入力、`05-todo` は進捗と次の行動を担う。機密性は `01-secret`、大容量の実体は `06-storage` を優先する（添付 workflow.md）。
- 04→02→03 は収集、整理・検証、目的に応じた活用の流れであり、単なる移動ではない。03の成果物には目的・想定読者・利用した知識を記し、必要な資料へリンクする（添付 workflow.md、output-readme.md）。
- タスクの進捗は05、成果物は03で管理し相互参照する。TODOは原則1タスク1ファイルで、一覧READMEは入口として使う（添付 todo-readme.md）。
- 作業手順は `agents/skills`、機械的な検査・変換は `scripts` が担い、手順からスクリプトを案内する（添付 skills-readme.md、scripts-readme.md）。

## 配置判断基準の提案

以下は根拠資料から導いた提案であり、確定ルールではない。

1. 内容の機能で分類する。全体の決まり・雛形は `00-rules`、再利用可能な整理済み知識は `02-knowledge`、目的に合わせた完成物・下書き・評価レポートは `03-output`、元資料や未整理入力は `04-materials`、進捗・完了条件は `05-todo`、機械処理は `scripts`、AIの作業手順は `agents/skills`。タスク定義と進捗、作業中の一時ファイル、テストデータ、実装物、評価結果、観測記録、再利用知識は役割で分け、同じディレクトリにあることだけで同一用途とみなさない。
2. 配置前に機密性とサイズを確認し、非公開情報は `01-secret`、大容量の実体は `06-storage` に置く。本文と説明は適切な公開区分に置いて実体へリンクする。
3. 個別タスク用ディレクトリは、関連する複数成果物をまとめる必要があり、既存の役割別ディレクトリでは見つけにくい場合に限る案とする。単一成果物や既存分類に収まるものは既存ディレクトリを使う。閾値は既存資料にないためユーザー判断が必要。
4. テストコードは実行対象と所有する機械処理を追える場所へ置く。提供資料では既存の機械処理とそのテストは `scripts/` と `scripts/test/` に分かれている。テストケース定義・入力データは評価手順が所有するケース領域（例: `agents/skills/skill-evaluation/cases/<case-id>/`）、評価結果は `03-output/skill-evaluation/` に置く案とする。評価結果には対象スキルまたは成果サンプル、ケースID、版ラベル、使用入力、採点結果を記す。テストケースは実行するテストと対象資産へ、評価結果はケース・対象資産の版・実行条件・テストまたは採点記録へ、TODOは該当するテスト・ケース・成果物へ相対リンクする。評価結果からケースと前回結果へ戻れるようにし、成果物からTODOへも相互参照する。既存添付ではcaseがsample-outputを参照し、結果がcaseとsampleを参照し、結果READMEが結果ファイルを列挙している。
5. TODOには要求・完了条件・進捗・次の行動を置き、実装物・観測記録・再利用知識はそれぞれの所有領域へ分ける。開発タスクでは `05-todo/development/` から開発先情報、04の元記録、02の知見へリンクする。作業中の一時ファイルは最終成果物と区別し、タスク実行に閉じた一時領域へ置き、恒久参照の対象にしない案とする。`.takt/runs/<run-id>/` は今回の資料ではTakt実行資料の場所として現れるが、汎用の一時作業領域としてよいかは未確認であり、配置ルール確定時に判断する。
6. 実装物は実行するプロジェクトまたは機械処理を所有する場所へ置き、説明・利用手順はREADMEや `agents/skills`、機械処理は `scripts` に案内を残す。観測記録・調査の元データは `04-materials`、整理・検証して再利用する知見は `02-knowledge` に置き、03の成果物から利用した知識・必要資料へリンクする。
7. 関連成果物は相対リンクで結ぶ。TODOから実装・テスト・ケース・成果物へ、成果物からTODO・利用知識・必要資料へ参照を設ける。移動・改名前に参照元を確認し、更新後にリンク検査する。履歴保持は未決定のため移動案ごとに確認する。

## 提案する標準構造

```text
.takt/runs/<run-id>/     作業中の一時ファイル候補（未確定・恒久リンクなし）
00-rules/                 全体ルール・テンプレート
01-secret/                非公開情報
02-knowledge/             整理・検証した再利用可能な知識
03-output/                記事・設計書・レポート・評価結果
  <topic>/                複数の関連成果物をまとめる場合のみ（提案）
  skill-evaluation/       評価結果（既存例。役割を維持）
04-materials/             元資料・観測記録・未整理入力
05-todo/                  タスク定義・進捗・成果物へのリンク
06-storage/               大容量ファイルの実体
agents/skills/<skill>/    AI向け作業手順
  skill-evaluation/cases/<case-id>/ ケース定義・入力・成果サンプル
scripts/                  機械的な処理
scripts/test/             scriptsの機械テスト（既存READMEの例）
```

`03-output/<topic>/` の追加条件、`.takt/runs/<run-id>/` を一般の一時作業領域として使えるか、テストコード・ケースの最終配置規約、評価レポートの命名規則は提案段階であり、確認前に既存ルールへ反映しない。現在の添付資料で確認できる既存例（`scripts/test/` と `agents/skills/skill-evaluation/cases/`、`03-output/skill-evaluation/`）は提案に反映した。
