# Markdownのコード表記内のパス参照を検査する

- 状態: 未着手
- 確認日: 2026-10-07
- 出典: 2026-10-07のユーザー依頼。社内で運用中のナレッジベースと比較し、こちらに無いスキル・機能をTODO化する依頼（Kiro対応とカレンダー取得は対象外と指示あり）。

## 目的

`scripts/check-knowledge-quality.mjs` はインラインリンクの参照先を検査するが、バッククォートで書いたパス（例: `scripts/xxx.sh`）は検査しない。ファイルの移動・削除後に手順書のパスが古いまま残ることを防ぐ。

## 要求

- 追跡済みMarkdownのインラインコード内の、リポジトリ内パスに見える文字列が実在するかを検査する。
- コマンド例・プレースホルダー（`<名前>` など）・ホームディレクトリなど、パスとして扱わないものを除外する規則を決める。
- ステージ済みファイルだけを検査するモードと、全体を検査するモードを用意する。

## 完了条件

- [ ] 存在しないパスを書いたMarkdownで検査が失敗する。
- [ ] 除外規則がREADMEに記載され、テストがある。
- [ ] 既存のMarkdownで違反が無いか、修正済みである。

## 次の行動

- [ ] 既存の `check-knowledge-quality.mjs` に観点を追加するか、別スクリプトにするかを決める。
