# ナレッジの鮮度・失効・再検証方法を定義する

- 状態: 完了（方針提案と限定試行。恒常運用への採用は未決定）
- 確認日: 2026-10-17
- 出典: 2026-10-06のユーザー依頼。時間経過や環境・ソフトウェア・方針の変更で古くなる知識を、種類に応じて再検証し、AIが古い内容を誤って現行情報として使わない方法を検討する依頼。

## 目的

知識が「いつ作られたか」だけで機械的に失効させず、その知識が当てはまる対象・条件・変化要因に応じて、再確認の必要性を人とAIが判断できるようにする。

## 背景

[知識メモの雛形](../../00-rules/templates/note.md)には確認日と「未確認 / 検証済み」の状態があるが、再検証の条件、期限、失効や置き換えの扱いは定義されていない。[Observation → Knowledge → Ruleのライフサイクル](../../agents/skills/knowledge-lifecycle/SKILL.md)は昇格条件を扱うが、Knowledgeの有効期間は扱っていない。

## 要求

- 技術情報、個人的な好み、設計方針、過去の事実、一時的な環境情報など、知識の種類ごとに鮮度の意味と再確認のきっかけを整理する。
- `active`、`stale`、`deprecated` 等の状態候補の意味、遷移、確認責任を検討する。名称・状態をそのまま採用することを前提としない。
- 有効期間やバージョン条件が有用な種類と、経過時間だけでは失効しない種類を区別する。過去の事実は当時の事実として保持し、現在にも当てはまるかを別に示せるようにする。
- 再検証の方法、結果の記録、未確認のまま残す場合の扱いを定義する。
- 新しい知識が古い知識に取って代わる場合は、旧記録を消さず、置き換え関係と適用時期・理由を追える方法を定める。
- AIが古い・未確認・適用条件不明の知識を見つけたとき、状態と確認日を示し、現行の確定情報として断定しない挙動を定義する。
- 既存の確認日・出典・未検証事項、04→02の昇格、および人が明示したときだけRuleへ昇格する原則と整合させる。
- 新しいメタデータ形式の一括導入や大量書き換えは行わず、必要性を確かめる小規模な試行と段階的な移行案を検討する。
