# タスク成果物の配置・構造ルールを整備する

- 状態: 未着手
- 確認日: 2026-10-04
- 出典: 同日の会話。リポジトリのルールに従っていない成果物や、タスク間で異なるディレクトリ構造・成果物形式を洗い出し、統一したいという依頼。

## 目的

タスクで作成する成果物の置き場所と構造を、リポジトリ全体の配置方針に沿って判断できるようにする。

## 要求

- タスク定義、作業中の一時ファイル、テストデータ、実装物、評価結果、観測記録、再利用可能な知見の役割を区別する。
- `00-rules/workflow.md`、README、各READMEの説明と矛盾しない配置・リンク規約を定義する。
- 個別タスクで追加するディレクトリの基準と、既存ディレクトリを使う基準を示す。
- 既存成果物を棚卸しし、移動・改名が必要な場合は参照リンクと履歴への影響を確認する。

## 完了条件

- [ ] 配置先を選ぶ判断基準と標準ディレクトリ構造が文書化されている。
- [ ] テストコード・ケースデータ・評価レポート等の配置ルールと相互リンクが明記されている。
- [ ] 現在の成果物との適合表を作り、ルール違反と単なる別用途を区別している。
- [ ] 必要な移動を行った場合、リンク切れがない。

## 次の行動

- [ ] 既存の `00-rules/workflow.md` と各領域READMEに重複・不足する規則を整理する。
