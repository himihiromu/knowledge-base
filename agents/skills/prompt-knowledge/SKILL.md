# 保存済みプロンプトから知識を整理する

## 目的

保存済みプロンプトを精査し、単発の記録として保留するか、繰り返し確認された知識として02へ整理するかを判断する。既存メモとの重複を避け、04の会話原文から02の知識へ出典をたどれるようにする。

## 使う場面

- `04-materials/prompts/` に保存されたプロンプトを見直すとき。
- 保存済みプロンプトから、再利用できる判断基準や技術的な知識を整理するとき。

## 入力

- 精査する保存済みプロンプトの原文とファイルパス。
- 原文に記録された発言者・発言日時・セッションの識別情報。今回の分析の確認日は出力側に記録する。元の情報が欠けている場合は推測で補わず、未確認事項として示す。
- 同じ分類または対象について過去に確認された記録と、必要に応じて確認できる根拠資料。
- 同じテーマを扱う02の既存メモ。保存先を固定せず、内容と適用範囲を比較して更新先を選ぶ。

## 原文・知識・分析の配置

| 役割 | 配置と扱い |
| --- | --- |
| 会話原文（ブロンズ） | [04-materials/prompts](../../../04-materials/prompts/README.md)の既存セッションを参照する。このスキルでは書き換え・再登録を行わず、抽出した方針・要約・分析・確認日を追記しない |
| 再利用可能な知識（シルバー） | [02-knowledge](../../../02-knowledge/README.md)の同じテーマの既存メモを優先して更新する。適切な既存メモがない場合だけ、1テーマ1ファイルで新規作成する |
| 分析・保留理由（ゴールド） | 作業報告に示す。レポートの保存が依頼範囲にある場合は[03-output](../../../03-output/README.md)の関連する分析レポートへ記録し、04の原文と02の関連メモへリンクする |

機密情報を含む知識・分析は01内に置く。01の資料を読む場合は、[agents.md](../../../agents.md)に従って依頼された範囲に限定する。公開可否が不明な内容は通常領域へ転記しない。

## 手順

知識化の判断では、以下の段階を順に確認する。

1. **原文を精査する**: 保存済みプロンプトを省略せず読み、要求、指摘、事実の主張、提案を区別する。文脈や根拠資料を確認できない主張は、確認済みの事実として扱わない。
2. **出典を確認する**: 原文の保存先、発言者、発言日時を確認する。原文の主張を裏付ける資料がある場合はその資料も確認する。資料本文を確認できない場合は、内容を推測せず未確認と記録する。
3. **機密性を確認する**: 機密情報を通常の知識や報告へ複写しない。04に機密情報が見つかった場合は、本文を引用せず隔離が必要なことを報告し、原文の移動・公開履歴への対応は依頼範囲に従う。知識化のために機密原文の複製を増やさない。
4. **ライフサイクルを判断する**: [知識ライフサイクル](../knowledge-lifecycle/SKILL.md)の昇格条件と数え方に従う。同一セッション内の再指摘も数え、指摘回数とセッション数を分けて示す。反復から分かる重要度と、知識として再利用できる適用範囲を別に判断し、根拠不足や明示的な保留は observation とする。頻度や回数だけで rule に昇格しない。rule にするのは、ユーザーが常時守らせたい意図を明示した場合に限る。会話原文と分析の配置は、上記の表と[原文アーカイブの規約](../../../04-materials/prompts/README.md)に従い、observationの解釈・仮分類・保留理由も04へ書き込まない。
5. **既存メモと照合する**: 02から同じテーマのメモを検索し、本文・適用範囲・出典を読む。同じ内容と根拠が記載済みなら「既存に含まれる」と報告し、追記や別ファイルの作成をしない。新しい根拠・適用条件・不足があれば、既存メモの必要な箇所だけを更新する。矛盾がある場合は双方の条件と出典を示し、上記ライフサイクルの関係確認手順に従う。重複候補を無断で統合・削除しない。
6. **知識を整理する**: knowledgeにできる内容を、選んだ既存メモまたは新しいテーマのメモへ整理する。[知識メモの雛形](../../../00-rules/templates/note.md)に沿って要点・詳細・状態・確認日・出典を残し、事実、解釈、未検証事項を分ける。単発や根拠不足の内容は分析・保留理由として報告する。お試し等で成果物を見てからユーザーが判断する依頼なら、保存前の草案と更新候補を提示する。
7. **既存原文へリンクする**: 知識メモから根拠となるすべてのセッションへ相対リンクを付け、関連する発言の日時や要旨を出典に記す。一時作業場所への絶対パスを恒久リンクにしない。原文を確認できない場合はリンクを推測で作らず、未確認として残す。
8. **確認して報告する**: 新規追加・既存更新・重複による見送り・根拠不足による保留を、理由と出典付きで示す。保存した場合は02や03の差分とリンク先を確認し、04に変更・追加がないことを確認する。確認できなかった範囲も報告する。

## 収集・保存スクリプトとの分担

- このスキルの入力は保存済みの会話であり、既存の原文を再登録しない。未保存の会話は先に[収集・登録手順](../../../scripts/README.md)の `register-ai-prompt-session.mjs` で発言者・時刻・原文のみの形式に登録する。機密区分は収集側で判断する。
- 知識の保存は、手順5・6で選んだ02のメモを編集して行う。会話登録スクリプトは02への追記を行わず、保存済み原文の知識化では呼び出さない。原文登録と知識の更新を一括で行う旧形式のスクリプトは廃止した。

## 出力先

- 元のobservation: 04の既存セッションを参照する。分析・保留理由は作業報告、保存する場合は03の分析レポートに置く。
- 繰り返しが確認されたknowledge: 02の適切な既存メモ、または既存にないテーマの新規メモ。重複だけなら変更なしとする。
- rule: 常時守らせたい意図がユーザーから明示された場合に限り、[知識ライフサイクルの判断手順](../knowledge-lifecycle/SKILL.md)に従って適切な保存先を選ぶ。
- 機密情報を含む知識・分析: 01内の該当するメモ。機密原文の収集・隔離は上記の分担と依頼範囲に従う。

## 確認方法

- 原文の出典・発言日時と、分析または知識の確認日が区別されていること。確認日を追加するために04を書き換えていないこと。
- 1件だけの記録を傾向として扱わず、2件以上でも繰り返しが確認できなければ knowledge に昇格していないこと。
- 同一セッションの再指摘を数え、指摘回数・セッション数・適用範囲を示していること。引用・複製・説明だけの補足を独立した指摘として増やしていないこと。
- 頻度だけで rule に昇格しておらず、常時守らせたい意図の明示がある場合はその出典が記録されていること。
- 知識メモの出典リンクから保存済みプロンプトの原文へたどれること。
- 機密情報が通常の知識領域へ転記されておらず、未検証の主張が検証済みとして記録されていないこと。
- 04に要約・抽出方針・分析を追記せず、原文を重複登録していないこと。
- 02の既存メモを確認し、追加・更新・見送りの理由を示していること。同じ入力を再確認しただけで重複した知識や原文を増やしていないこと。
