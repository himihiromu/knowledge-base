# Observation → Knowledge → Ruleのライフサイクル判断

指摘や気づきを、observation（1回の記録）→ knowledge（複数回の確認で整理）→ rule（常時守らせたい意図の明示）の3段階で扱い、段階の昇格条件と、各段階の確認方法・出典・保存先を既存の配置ルールへ対応付けるスキル。

## 目的

1回の指摘は記録して傾向を待ち、繰り返し確認された内容だけを知識へ整理する。ルールへ昇格させるのは、ユーザーが常時守らせたい意図を明示した場合のみに限定する。単発の指摘から恒久ルールを断定せず、頻度・回数だけを根拠にルールを増やすことを防ぐ。

## 使う場面

- 作業の修正を求める指摘や、新しく気づいた方針・好みを受け取ったとき。
- 記録した指摘が複数回たまり、知識として整理してよいか判断するとき。
- 知識をルールとして常時守らせるかどうか、どこに置くか判断するとき。

## 入力

- 指摘・気づき1件以上。出典（ユーザーの発言、レビュー、実行結果など）と確認日が分かるもの。
- 指摘を受けた作業の手順、またはその対象ファイル。

## 原則

- 1回の指摘は observation として記録し、恒久ルールへ断定しない。頻度・回数は knowledge へ昇格する根拠であり、rule へ昇格する根拠にしない。
- rule へ昇格させるのは、ユーザーが常時守らせたい意図を明示した場合のみ。AIが複数回の指摘から一般化して rule を作らない。
- [原因特定・変更箇所判断](../../../agents/skills/correction-analysis/SKILL.md)の「傾向が見えるまで変更しない」方針に従い、傾向が確認できない指摘は変更を掛けず記録を続ける。ユーザー自身の明示による rule 化は、この保留の対象外である。
- 手順内の例は架空の例である。架空の例を、ユーザーの実際の指摘や好みとして `04-materials/` や `02-knowledge/` に保存しない。

## 3段階の定義

| 段階 | 扱う内容 | 保存先 | 出典・確認日 | 確認方法 |
|------|----------|--------|--------------|----------|
| observation | 1回の指摘・気づき。仮分類と出典を記録し、傾向判断の材料として保留する | [04-materials](../../../04-materials/README.md)（ブロンズ・未整理の入力）。原因特定・変更箇所判断の記録先 `04-materials/correction-notes.md` に1指摘1節で追記する。AIとのプロンプトの原文は [04-materials/prompts](../../../04-materials/prompts/README.md) にスクリプトで保存する | 1件ずつ出典と確認日を残す | 各記録に出典と確認日があること。傾向が見えるまで変更を掛けないこと |
| knowledge | 同じ分類・同じ対象の確認が複数回あり、傾向分析で繰り返しが確認できた判断基準・技術メモ | [02-knowledge](../../../02-knowledge/README.md)（シルバー）。[知識メモの雛形](../../../00-rules/templates/note.md)を使う | 要点・詳細・出典・確認日を残し、元の04の記録へ出典リンクを付ける。事実・推測・未検証事項を区別する | 出典リンクが解決すること。未検証の手順は未検証と記載されていること |
| rule | 常時守らせたい意図が明示された運用・手順・機械検査 | 全作業に共通する運用ルールは[00-rules](../../../00-rules/workflow.md)。特定の作業の手順は[agents/skills](../../../agents/skills/README.md)。機械的な検査・変換は[scripts](../../../scripts/README.md) | 変更理由・出典・確認日を残し、既存メモとの重複・矛盾を先に確認する | 配置ルールの位置に合うこと。意図の明示の出典が残っていること |

## 昇格条件

- **observation → knowledge**: 同じ分類または同じ対象の確認が2件以上たまり、[原因特定・変更箇所判断](../../../agents/skills/correction-analysis/SKILL.md)の手順4の傾向分析で繰り返しが確認できたこと。1件だけの指摘は observation のまま保留する。
- **knowledge → rule**: ユーザーが常時守らせたい意図を明示したこと。頻度・傾向だけでは昇格しない。明示があれば確認回数にかかわらず rule として扱え、明示がなければ複数回確認されても knowledge のまま保留する。
- 昇格はファイルの移動ではなく、整理・検証・用途に応じた編集である（[運用ルール](../../../00-rules/workflow.md)のメダリオンアーキテクチャ）。昇格時に出典へのリンクを維持する。

## 手順

1. **observationとして記録する**: 指摘・気づき1件を、出典と確認日付きで04-materialsへ記録する。原因特定・変更箇所判断の手順1と同じ記録先を使い、分類は仮分類として残す。
2. **傾向を確認する**: 同じ分類・同じ対象の確認が2件以上たまったら、原因特定・変更箇所判断の手順4の傾向分析を行う。繰り返しが確認できない間は変更を掛けず、記録を続ける。
3. **knowledgeへ整理する**: 傾向が確認できた内容を02-knowledgeへ整理する。雛形で要点・詳細・出典・確認日を残し、元の04の記録へ出典リンクを付ける。
4. **ruleへ昇格するか判断する**: 常時守らせたい意図の明示がある場合のみ rule へ昇格する。保存先は1つ選ぶ。
   - 00-rules: 複数の作業に共通する運用ルールの不足・誤り。
   - agents/skills: 対象の作業手順そのものの不足・誤り。
   - scripts: 機械的な検査・変換で防げるもの。追加するときは[scriptsの記録規定](../../../scripts/README.md)に従う。
   明示がない内容は、複数回確認されていても knowledge のまま保留する。
5. **昇格時に整理・検証する**: rule として書く内容を運用ルールの書式に整え、既存メモとの重複・矛盾を先に確認する。判断を変えた場合は理由を出典とともに残す。
6. **確認して報告する**: 各段階の記録が確認方法の条件を満たすこと、昇格した内容の出典リンクが維持されていることを確認する。変更したファイルと残った未確認事項を報告する。

## 関係がある知識の変更

[関連知識の絞り込み](../filter-related-knowledge/SKILL.md)で人が確認した関係を、知識の昇格・変更時にも参照する。関係候補だけを根拠に知識を昇格、上書き、削除しない。

- `contradicts` を記録するときは、両方の対象箇所・出典・適用条件・確認日と、両立しない理由を残す。条件が違う場合は矛盾と断定せず、条件の違いを記録する。
- `supersedes` を記録するときは、新しい知識から旧知識へリンクし、旧情報の有効範囲、置き換え理由、確認日を残す。旧知識とその出典は削除・統合せず、旧条件に関する参照可能性を維持する。
- 知識の変更は、人が関係と根拠を確認した後に通常の昇格・変更手順として行う。変更後も相対リンクと出典をたどれることを確認する。

## 出力先

- observation の記録: `04-materials/correction-notes.md`（原因特定・変更箇所判断と同じ記録先。スキル実行時に作る）。
- knowledge の整理先: [02-knowledge](../../../02-knowledge/README.md)（[知識メモの雛形](../../../00-rules/templates/note.md)を使用）。
- rule の反映先: 00-rules、agents/skills、scripts のいずれか（手順4の判断による）。
- 実施したタスクの状態: [05-todo](../../../05-todo/README.md)の該当項目を更新する。

## 確認方法

- 記録した各指摘・各知識に出典と確認日が残っていること。
- 傾向が確認できない指摘を、ルール・知識として反映していないこと。
- rule へ昇格した内容に、常時守らせたい意図の明示とその出典が残っていること。頻度・回数だけを根拠に昇格していないこと。
- 昇格時に整理・検証が行われ、出典へのリンクが維持されていること。

## 例（架空の記録。実在の指摘・好みではない。このまま保存しない）

```
- 確認日: 2026-10-01（架空の例）
- 出典: 架空のレビュー指摘（1回目）
- 段階: observation
- 内容: 追記したメモに出典が書かれていない
- 仮の原因候補: 出典の書き方を案内する手順が無い
- 保存先: 04-materials の記録ファイル。変更は掛けない
```

```
- 確認日: 2026-10-02（架空の例）
- 出典: 架空のレビュー指摘（2回目）
- 段階: knowledge へ昇格
- 判断根拠: 同じ対象（メモ追記時の出典記載）の確認が2件で、傾向分析で繰り返しを確認
- 保存先: 02-knowledge へ要点・出典リンク付きで整理
```

```
- 確認日: 2026-10-03（架空の例）
- 出典: 架空のユーザー発言「メモへは必ず出典を書くよう常時守らせたい」
- 段階: rule へ昇格
- 判断根拠: 常時守らせたい意図の明示。頻度は根拠にしない
- 保存先: agents/skills（メモ追記という特定の作業の手順として）
```

この例は手順の説明用であり、ユーザーの実際の指摘や好みとして `04-materials/` や `02-knowledge/` に保存しない。実際の指摘は原因特定・変更箇所判断の手順1の記録先へ、実施した作業として記録する。
