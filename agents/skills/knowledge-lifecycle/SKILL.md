# Observation → Knowledge → Ruleのライフサイクル判断

## 目的・使う場面

指摘・気づきを受け取ったとき、または保存済みの記録を見直すときに、再利用する知識へ整理するか、根拠不足で保留するかを判断する。常時適用する意思が明示された内容はルールとして扱う。

## 入力

- 指摘の原文、出典、発言日時、セッションの識別情報。欠けている情報は推測で補わない。
- 先行する依頼、指摘対象の成果物・応答、その後の修正など、指摘の意味を確認できる文脈。
- 同じ判断基準に関する他の発言と、02の既存知識・適用中のルール。

## メダリオンに沿った配置

段階は知識としての扱いを表す。段階名だけで保存先を決めず、内容の役割で分ける。[共通の運用ルール](../../../00-rules/workflow.md)を参照先のスキルにも適用する。

| 内容 | 配置と扱い |
| --- | --- |
| 指摘の原文・元資料 | 04（ブロンズ）の既存資料を参照する。会話は[原文アーカイブ](../../../04-materials/prompts/README.md)を使い、再登録や分析の追記をしない |
| 仮分類・原因の推測・重要度の評価・保留理由・昇格判断 | 作業報告。保存が依頼範囲にある場合は03（ゴールド）のテーマ別分析レポートに記録し、04と関連する02へリンクする |
| 根拠と適用条件を整理した再利用知識 | 02（シルバー）の同じテーマのメモを優先して更新する |
| 常時適用する意思が明示されたルール | 内容に応じて00-rules、agents/skills、scripts。原文・分析・知識とは役割を分ける |
| 作業の進捗 | 05の該当タスク |

04に仮分類や分析を保存する案内が他のスキルに残っていても、上の配置に従う。機密性を優先し、非公開情報は01内で扱う。01の参照は依頼された範囲に限り、公開可否が不明な本文を通常の報告へ引用しない。

## 反復の数え方と昇格条件

- **observation（観測・保留）**: 1回の指摘、または反復はあっても再利用できる判断基準・適用条件が未確定の内容。原文と分析者の解釈を分けて示す。
- **knowledge（再利用知識）**: 同じ具体的な判断基準への指摘が複数回あり、文脈を確認して再利用できる内容と適用範囲を説明できる場合に整理する。同一セッション内の繰り返しも数え、重要度の根拠として扱う。異なる2セッションを必須条件にしない。
- **rule（常時適用する規則）**: ユーザーが常時守らせたい意思と対象範囲を明示した場合に限る。反復回数にかかわらず扱える。回数や重要度だけで昇格させない。

指摘回数とセッション数を分け、たとえば「指摘3回・1セッション」と報告する。数えた発言の日時・要旨と前後関係を示し、ユーザーが改めて修正・要求した発言を1回として扱う。会話の複製、引用、別エージェントへの転記、アシスタントの言い換え、説明だけの補足を独立した指摘として加算しない。

同じ作業で修正が反映されず繰り返された指摘は、その作業での重要度を示す根拠になる。そこで確認できた好みの適用範囲は別に判断する。繰り返しが同じ作業だけでも、対象や条件を限定して再利用できるなら知識化できる。別の作業や画面にも当てはまるとは推測しない。明示された保留は維持する。

## 手順

1. **原文と文脈を確認する**: 指摘を先行する依頼・応答・修正結果と合わせて読む。事実、ユーザーの要望、分析者の推測を区別する。保存済み原文は参照し、未保存の会話の収集が必要なら[収集・登録手順](../../../scripts/README.md)へ分ける。
2. **反復と適用範囲を整理する**: 上記の基準で指摘回数とセッション数を記録する。同じ判断基準か、条件の異なる別の要望かを確認する。原因の分析が必要な場合は[原因特定・変更箇所判断](../correction-analysis/SKILL.md)を使い、分析は作業報告または03へ置く。
3. **既存の知識・ルールと照合する**: 本文・適用条件・出典を比較する。同じ内容と根拠があれば追加を見送る。新しい根拠や条件は既存メモの必要な箇所へ反映し、適切なメモがない場合だけ新規作成する。
4. **段階と変更先を判断する**: 根拠不足ならobservationとして保留する。knowledgeなら[知識メモの雛形](../../../00-rules/templates/note.md)に沿って02へ整理する。ruleなら明示された範囲に合わせ、全作業の運用は00、個別作業の手順はスキル、機械処理はスクリプトを変更対象にする。お試しでユーザーが成果物を見て判断する依頼では、保存前の草案を提示する。
5. **出典を残して報告する**: 判定、理由、適用範囲、指摘回数・セッション数、発言日時と原文へのリンク、未確認事項を示す。分析・知識の確認日を原文の発言日時と区別する。保存した場合は差分と相対リンク、04が変更されていないことを確認する。今回の依頼の実行と、将来の知識・ルール化は別に判断し、単発という理由で依頼された修正を保留しない。

## 関係がある知識の変更

[関連知識の絞り込み](../filter-related-knowledge/SKILL.md)の関係候補だけを根拠に知識を上書き・削除しない。人が関係と根拠を確認した後に変更する。

- `contradicts`: 双方の対象箇所・出典・適用条件・確認日と、両立しない理由を残す。条件の違いを矛盾と断定しない。
- `supersedes`: 新しい知識から旧知識へリンクし、旧情報の有効範囲と置き換え理由を残す。旧知識とその出典は削除・統合せず、参照可能性を維持する。

## 確認方法

- 原文は04、解釈・分析・保留理由は作業報告または03、整理した知識は02になっている。
- 指摘回数とセッション数を混同せず、同一セッションの再指摘も根拠に含め、単なる複製・補足は重複計上していない。
- 重要度と適用範囲を別に示し、回数だけで知識・恒常ルールへ昇格させていない。
- 既存メモとの重複・矛盾を確認し、出典、確認日、未確認事項を追える。
- 架空の説明例をユーザーの実際の好みとして保存していない。

## 例（架空。実データとして保存しない）

| 入力 | 判定・出力 |
| --- | --- |
| 同じセッションで、修正のたびに「この一覧では0件の項目を隠して」と3回指摘 | 指摘3回・1セッション。その一覧での重要度は高い。再利用条件が確認できればその一覧に限定した知識候補とし、他の画面への適用は未確認とする |
| 上記の会話が別エージェントへそのまま転記された | 元の3回の根拠を参照する。新しい指摘や独立した根拠として増やさない |
| 「表示項目の好みかもしれないが、条件が難しいので保留」と補足 | 新しい修正要求として加算せず、解釈と保留理由を作業報告へ反映する |
| 1回でも「会話アーカイブには常に原文だけを保存して」と明示 | そのアーカイブのルールとして扱い、既存の規約と照合する |
