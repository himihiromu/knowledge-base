# commit前ナレッジ検査

## 目的

commitする前に、ステージ済みのナレッジ差分へ本文として背景・経緯・日時が混ざっていないかを確認する。

検出の対象と、確認日・出典を残す既存の運用は次のように分かれる。

- 検出対象: 本文に書かれた日付・時刻、経緯・背景・きっかけを示唆する語。ナレッジは要点として残し、いつ・なぜの記述は出典や経緯の記録に寄せるための確認である。
- 検出除外: `- 確認日:`・`- 記録日:`・`- 作成日:`・`- 更新日:`・`- 取得日:`・`- 状態:` の行頭箇条書きと `## 出典` セクション内の行。これらは[運用ルール](../../../00-rules/workflow.md)とテンプレートが定める正規のメタデータであり、検出の対象外で、残す。

検出されても必ずしも問題ではない。判定はこの手順に従い、スクリプトは候補の列挙のみを行う。

## 使う場面

`git add` の後、commitの前。[運用ルール](../../../00-rules/workflow.md)の「Gitに保存する前に差分を確認し」の確認の一部として実施する。

## 入力

ステージ済みの差分（`git diff --cached`）。作業ツリー・ステージ・既存ファイルは変更しない。

## 手順

1. `git status --short` や `git diff --cached --stat` で、ステージ済み差分があることを確認する。
2. `node scripts/check-knowledge-diff.mjs` を実行する。パスを引数に渡すと差分を絞り込める（例: `node scripts/check-knowledge-diff.mjs 02-knowledge`）。`01-secret/`・`06-storage/`・`99-trash/`・`.takt/` 配下は常に除外される。
3. 出力された候補を1件ずつ判定する。
   - 本文に確定の日時や経緯の説明が書かれている場合: 記録すべき内容は出典・確認日・資料メモへ移すべき候補として、修正の必要を利用者へ報告する。
   - メタデータ相当や、日付が本質的な意味を持つ記録（例: 04-materialsの資料メモの記録日、会話の日付の出典）の場合: 例外として扱う。
4. 例外と判断した候補は、判定理由を添えて報告する。差分そのものは書き換えない。
5. ファイルの修正・削除はユーザーの依頼がある場合のみ行う。検出を理由にした無断の一括削除・自動修正をしない。運用ルールの本文は変更しない。

nodeを使えない環境では、`git diff --cached` の追加行（`+` で始まる行）を手動で読み、手順3と同じ基準で日付・時刻・経緯語（経緯・背景・きっかけ）を確認する。除外基準も同じく、行頭のメタデータ箇条書きと `## 出典` セクション内の行。

## 出力先

- スクリプトは標準出力へ、候補の一覧（ファイル・行番号・カテゴリ・該当行）と除外件数を出す。
- 終了コード: 0=検出なし、1=検出あり、2=実行環境エラー。
- 判定結果（修正の要否と例外の理由）はcommit前の差分確認の報告に含める。スクリプト自身はファイルを書き換えない。

## 確認方法

- スクリプトの目的・実行方法・依存ツール・変更対象は[scripts/README.md](../../../scripts/README.md)に記録してある。
- スクリプトの機械的な確認は `node --test scripts/test/check-knowledge-diff.test.mjs` を実行する。
- メタデータを除外する根拠は[運用ルール](../../../00-rules/workflow.md)とテンプレート（`00-rules/templates/`）。
