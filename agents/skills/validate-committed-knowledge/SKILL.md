# commit前ナレッジ検査

## 目的

commitする前に、ステージ済みのナレッジ差分へ本文として背景・経緯・日時が混ざっていないかを確認する。

検出の対象と、確認日・出典を残す既存の運用は次のように分かれる。

- 検出対象: 本文に書かれた日付・時刻、経緯・背景・きっかけを示唆する語。ナレッジは要点として残し、いつ・なぜの記述は出典や経緯の記録に寄せるための確認である。
- 検出除外: `- 確認日:`・`- 記録日:`・`- 作成日:`・`- 更新日:`・`- 取得日:`・`- 状態:` の行頭箇条書きと `## 出典` セクション内の行。これらは[運用ルール](../../../00-rules/workflow.md)とテンプレートが定める正規のメタデータであり、検出の対象外で、残す。

検出されても必ずしも問題ではない。判定はこの手順に従い、スクリプトは候補の列挙のみを行う。

リンク切れ・orphan・重複・矛盾・必須メタデータなど、commit後のナレッジ全体を機械で判定できる品質検査は `scripts/check-knowledge-quality.mjs` が担い、CI（`.github/workflows/knowledge-quality.yml`）で実行される。この手順は差分に特化した確認であり、機械検査との分担の詳細は[scripts/README.md](../../../scripts/README.md)に記録してある。

## 使う場面

`git add` の後、commitの前。[運用ルール](../../../00-rules/workflow.md)の「Gitに保存する前に差分を確認し」の確認の一部として実施する。

## 入力

ステージ済みの差分（`git diff --cached`）と、候補があるファイルのステージ済み本文（`git show :リポジトリ相対パス`）。検出対象は差分の追加行のみ。本文は出典節の所属判定に使い、未変更の行を候補として増やさない。未ステージの編集を判定に混ぜず、作業ツリー・ステージ・既存ファイルは変更しない。

## 手順

1. `git status --short` や `git diff --cached --stat` で、ステージ済み差分があることを確認する。
2. `node scripts/check-knowledge-diff.mjs` を実行する。既定では02以外も含めたステージ済み差分を検査する。パスを引数に渡すと差分を絞り込める（例: `node scripts/check-knowledge-diff.mjs 02-knowledge`）。`01-secret/`・`06-storage/`・`99-trash/`・`.takt/` 配下は差分取得時に除外し、その本文も取得しない。出典節は差分に見出しがなくてもステージ済み本文から判定する。本文の取得失敗は検査エラーとして報告する。
3. 出力された候補を1件ずつ判定する。
   - 02の要点に作業履歴や分析が混ざる場合: 事実の根拠は出典、知識の確認日はメタデータ、分析・判断過程は作業報告または03、進捗・作業履歴は05へ分ける修正案を示す。02には再利用する知識と適用条件を残す。日時が適用条件や知識の意味に必要なら残す。
   - 原文・資料そのものの日付、03の分析日時、05の履歴、00やスキルの変更根拠など、役割に必要な記述は理由を添えて残す。04の原文に含まれる日時・背景語は原文として保持し、分析を04へ移す案や原文の書き換えを提案しない。
4. 例外と判断した候補は、判定理由を添えて報告する。差分そのものは書き換えない。
5. ファイルの修正・削除はユーザーの依頼がある場合のみ行う。検出を理由にした無断の一括削除・自動修正をしない。運用ルールの本文は変更しない。

nodeを使えない環境では、対象パスを明示して `git diff --cached -- 対象パス` の追加行を読み、手順3と同じ基準で確認する。上記の除外パスは読まない。所属セクションは `git show :リポジトリ相対パス` の本文で確認する。未ステージの作業ファイルや、見出しの欠けた差分だけから所属を推測しない。

## 出力先

- スクリプトは標準出力へ、候補の一覧（ファイル・行番号・カテゴリ・該当行）と除外件数を出す。
- 終了コード: 0=検出なし、1=検出あり、2=実行環境エラー。
- 判定結果（修正の要否と例外の理由）はcommit前の差分確認の報告に含める。スクリプト自身はファイルを書き換えない。
- レポートの保存が依頼範囲にある場合は03へ置き、対象差分・出典へリンクする。検査のために04へ要約・分析・原文の複製を追加しない。[共通の配置規定](../../../00-rules/workflow.md)に従う。

## 確認方法

- スクリプトの目的・実行方法・依存ツール・変更対象は[scripts/README.md](../../../scripts/README.md)に記録してある。
- スクリプトの機械的な確認は `node --test scripts/test/check-knowledge-diff.test.mjs` を実行する。
- メタデータを除外する根拠は[運用ルール](../../../00-rules/workflow.md)とテンプレート（`00-rules/templates/`）。
- 差分から出典見出しが省略された場合や、作業ツリーとステージが異なる場合も、ステージ済み本文を基準に追加行だけを判定していること。
