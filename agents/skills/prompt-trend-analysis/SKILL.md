# AIプロンプトの収集と傾向分析

Claude CodeとCodexのユーザー入力をセッション単位で収集し、成果物や進め方に対する後続の指摘・修正から、繰り返し現れる好みや判断基準を根拠付きで整理する。

## 使う場面

- Claude CodeまたはCodexでの過去の指示から、継続する傾向を確認したいとき。
- 04に保存したセッション記録を比較し、02の知識や作業ルールへ昇格する根拠を確認するとき。

## 入力

- 収集対象の期間（任意。省略時は全期間）。
- `04-materials/prompts/` のセッション記録。機密情報を含む記録は01に保存し、通常の分析対象へ本文を転記しない。
- 必要に応じて、指摘があった作業や対象の成果物。

## 手順

1. **セッション単位で収集する**: `node scripts/fetch-ai-prompts.mjs [--since YYYY-MM-DD] [--until YYYY-MM-DD]` を実行する。既定は1行1セッションで、Claude/Codexのユーザー発言を時系列に保持する。アシスタントの返答は含まれない。日付を指定した場合、期間内に発言があるセッションを選び、そのセッションの期間外の発言も文脈として含める。
2. **内容を確認して保存する**: 収集JSONLから分析に使うセッションを選び、セッション本文に機密情報や公開可否が不明な個人情報があれば `register-ai-prompt-session.mjs --secret` で01へ保存する。それ以外は `register-ai-prompt-session.mjs --title "内容が分かる題名" --file セッションJSON` で04へ保存する。セッション原文を共有・コミットする前にも内容を確認する。
3. **フィードバックをタスク依頼から分ける**: 作業開始時の依頼、PR作成依頼、障害調査依頼などは、成果物への指摘が含まれない限り好みの根拠にしない。後続のユーザー発言から、誤りの指摘、期待とのずれ、採用・除外の判断、修正要求を探す。
4. **元セッションで前後関係を確認する**: 収集データはユーザー発言のみなので、候補ごとにローカルの元セッションを開き、先行する依頼、直前のアシスタント応答、後続の指摘を読む。アシスタント応答は指摘の対象を理解するためだけに使い、ユーザーの好みとして記録しない。確認できない場合は因果関係を断定しない。
5. **比較単位を決める**: 指摘を内容ごとに分類し、同一セッション内の複数発言をまとめる。反復数は異なるセッション数で示し、収集対象の総数を好みの証拠数と混同しない。
6. **単発と反復を分ける**: 1セッションだけの要望は単発Observationとして扱う。同じ具体的な判断基準が異なる2セッション以上で確認できる場合に限り傾向候補とする。異なる事例の共通点が曖昧なら、候補を統合せず追加観測とする。2件以上でも自動的に恒常ルールへ昇格しない。
7. **分析結果を記録する**: `04-materials/` に確認日、分析範囲、指摘の前後関係、セッション単位の根拠、単発の例、出典リンク、未確認事項を記録する。ユーザーが明示した内容、分析者の解釈、未確認事項を分ける。過剰な原文収録を避け、必要最小限の引用にする。
8. **ライフサイクルに沿って昇格する**: 反復が確認できた再利用可能な判断基準は、元セッションへのリンクを付けて02へ整理する。常時適用する意思がユーザーから明示されている場合に限り、Ruleとして該当する手順へ反映する。今回のタスク固有の判断を恒常的な好みへ一般化しない。

## 出力

- 未確定の分析記録: `04-materials/` のテーマ別分析メモ。
- 確認済みの再利用可能な知識: `02-knowledge/` の適切な既存テーマまたは新規メモ。
- 明示的に恒常適用する指示: 該当する `agents/skills/` または `00-rules/`。
- 元記録は04に残し、分析結果から相対リンクで追跡できるようにする。

## 確認方法

- 分析対象がClaude/Codexのユーザー入力であり、出典と確認日が記録されている。
- 同一セッション内の複数発言を別々の反復件数として数えていない。
- 各傾向候補に複数セッションの出典と前後関係があり、単発の例と未確認事項が区別されている。
- タスク依頼や作業種類の反復を、成果物への好みとして数えていない。
- 01の機密内容を通常領域へ転記していない。
- 02やRuleへ昇格した場合、出典リンクと昇格理由があり、Ruleには明示的な恒常適用の意思がある。
