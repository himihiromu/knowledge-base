# AIプロンプトの収集と傾向分析

Claude CodeとCodexの可視会話をセッション単位で収集し、成果物や進め方に対するユーザーの後続の指摘・修正から、繰り返し現れる好みや判断基準を根拠付きで整理する。

## 使う場面

- Claude CodeまたはCodexでの過去の指示から、継続する傾向を確認したいとき。
- 04に保存したセッション記録を比較し、02の知識や作業ルールへ昇格する根拠を確認するとき。

## 入力

- 収集対象の期間（任意。省略時は全期間）。
- `04-materials/prompts/` のセッション記録。機密情報を含む記録は01に保存し、通常の分析対象へ本文を転記しない。
- 必要に応じて、指摘があった作業や対象の成果物。

## 手順

1. **セッション単位で収集する**: 未保存の会話を収集する場合は `node scripts/fetch-ai-prompts.mjs [--since YYYY-MM-DD] [--until YYYY-MM-DD]` を実行する。既定は1行1セッションで、Claude/Codexのユーザー・アシスタントの可視発言を時系列に保持する。日付を指定した場合、期間内に発言があるセッションを選び、そのセッションの期間外の発言も文脈として含める。保存済みの04を分析する依頼では手順3から進める。
2. **全文を04へ保存する**: `node scripts/register-ai-prompt-session.mjs --batch --file セッションJSONL` で未保存の会話履歴を1セッション1ファイルとして登録する。04の本文にはユーザー・アシスタントの可視発言だけを原文で保存し、要約や傾向を書かない。既存原文は再登録しない。個人情報・認証情報などを含むセッションは通常の04へ公開せず、既存の機密情報ルールに従う。
3. **フィードバックをタスク依頼から分ける**: 作業開始時の依頼、PR作成依頼、障害調査依頼などは、成果物への指摘が含まれない限り好みの根拠にしない。後続のユーザー発言から、誤りの指摘、期待とのずれ、採用・除外の判断、修正要求を探す。
4. **元セッションで前後関係を確認する**: 候補ごとに04の元セッションを開き、先行する依頼、直前のアシスタント応答、後続の指摘を読む。アシスタント応答は指摘の対象を理解するためだけに使い、ユーザーの好みとして記録しない。確認できない場合は因果関係を断定しない。
5. **比較単位を決める**: [知識ライフサイクルの数え方](../knowledge-lifecycle/SKILL.md)に従って指摘を分類する。同一セッションの再指摘も数え、指摘回数とセッション数を分けて示す。数えた発言の日時・要旨を追えるようにし、複製・引用・説明だけの補足は加算しない。
6. **単発と反復を分ける**: 同じ具体的な判断基準への反復を確認し、重要度と再利用できる適用範囲を別に示す。同一セッションだけでも、範囲を限定して知識候補にできる。異なる事例の共通点や適用条件が曖昧なら保留する。回数だけで知識や恒常ルールへ昇格しない。
7. **分析結果を記録する**: 分析は作業報告へ示し、保存が依頼範囲にある場合は `03-output/` に置く。確認日、分析範囲、指摘の前後関係、指摘回数・セッション数、適用範囲、単発の例、04の原文記録へのリンク、未確認事項を記録する。ユーザーが明示した内容、分析者の解釈、未確認事項を分ける。[共通の配置規定](../../../00-rules/workflow.md)を参照先のスキルにも適用する。
8. **ライフサイクルに沿って昇格する**: 反復が確認できた再利用可能な判断基準は、元セッションへのリンクを付けて02へ整理する。常時適用する意思がユーザーから明示されている場合に限り、Ruleとして該当する手順へ反映する。今回のタスク固有の判断を恒常的な好みへ一般化しない。

## 出力

- 未確定の分析記録: 作業報告。保存する場合は `03-output/` のテーマ別分析レポート。
- 確認済みの再利用可能な知識: `02-knowledge/` の適切な既存テーマまたは新規メモ。
- 明示的に恒常適用する指示: 該当する `agents/skills/` または `00-rules/`。
- 04には会話原文のみを残し、分析レポートから相対リンクで追跡できるようにする。

## 確認方法

- 分析対象がClaude/Codexのユーザー入力であり、出典と確認日が記録されている。
- 同一セッション内の再指摘を含めた指摘回数とセッション数が別に示され、複製・引用・補足を重複計上していない。
- 各傾向候補に原文の出典と前後関係、適用範囲があり、重要度と一般化の根拠を区別している。
- タスク依頼や作業種類の反復を、成果物への好みとして数えていない。
- 01の機密内容を通常領域へ転記していない。
- 02やRuleへ昇格した場合、出典リンクと昇格理由があり、Ruleには明示的な恒常適用の意思がある。
