# AIとのプロンプトの傾向分析

保存済みのAIプロンプトを比較し、繰り返し現れる好み・指摘・判断基準を、元の記録へたどれる形で整理する。

## 使う場面

- 保存済みプロンプトに同じ分類または同じ対象の指摘が複数回あるか確認するとき。
- 単発の要望を継続的な傾向と誤認せず、knowledgeとして整理する根拠を確認するとき。
- 既存のknowledgeがどのプロンプト記録に基づくか確認するとき。

単一のプロンプトを記録・分類する作業は[プロンプト内容のナレッジ化手順](../../../05-todo/tasks/prompt-knowledge-skill.md)の対象とする。このスキルは保存済みの複数記録を比較する。プロンプト原文の取得・保存は[プロンプト保存スクリプトの案内](../../../scripts/README.md)に従い、このスキルでは行わない。

## 入力

- `04-materials/prompts/` に保存された対象期間または対象テーマのプロンプト記録。
- 各記録の出典と確認日。確認できない場合は不明として扱う。
- 必要に応じて、既存の `04-materials/correction-notes.md` および関連する `02-knowledge/` のメモ。

通常の検索では `01-secret/`、`06-storage/`、`99-trash/` を対象にしない。機密情報を扱う必要がある場合は通常の知識領域へ転記せず、機密領域の規則に従う。

## 判断基準

- 1件の要望・指摘は単発の観察として扱い、継続的な傾向と断定しない。
- [knowledge-lifecycle](../knowledge-lifecycle/SKILL.md)に従い、同じ分類または同じ対象の記録が2件以上あり、比較して繰り返しが確認できた場合に限りknowledgeへ整理する。件数だけで昇格せず、内容が同じ傾向を示すか確認する。
- knowledgeからruleへ進めるのは、ユーザーが常時守らせたい意図を明示した場合だけとする。頻度や傾向からruleを作らない。
- 出典、確認日、事実・推測・未検証事項を分ける。記録のない出典や日付を補わない。

## 手順

1. 対象範囲を決め、対象プロンプト記録と既存の関連メモを確認する。
2. 各記録から観察した好み・指摘・判断基準を抜き出し、分類と対象を仮にそろえる。原文の意味を超えて一般化しない。
3. 各観察に出典リンクと確認日を対応付け、同じ分類または対象の記録を比較する。
4. 1件だけ、または繰り返しを確認できない場合は傾向として扱わず、観察を `04-materials/correction-notes.md` に記録する。既存の記録形式に沿い、出典と確認日を残す。
5. 2件以上で繰り返しが確認できた場合は、事実と推測を分けて `02-knowledge/` に整理し、各元記録への相対リンクと確認日を付ける。知識メモの雛形を使う。
6. 常時守らせたい意図がユーザーから明示されている場合に限り、knowledge-lifecycleの判断に従ってruleへの反映先を選ぶ。既存文書との重複・矛盾を確認し、変更理由と出典を記録する。
7. 出典リンクの解決、保存先、判断根拠、未確認事項を確認して結果を報告する。

## 出力先

- 単発または未確認の観察: `04-materials/correction-notes.md`。未作成なら、knowledge-lifecycleと原因特定・変更箇所判断スキルの手順に従って作成する。
- 繰り返しが確認された知識: [`02-knowledge/`](../../../02-knowledge/README.md)。知識メモの雛形を使用する。
- 明示された意図に基づくrule: 対象に応じて `00-rules/`、`agents/skills/`、または `scripts/` のうち1か所。
- タスク状態と成果物リンク: [`05-todo`](../../../05-todo/README.md) の該当タスク。

## 確認方法

- 分析した各観察から元のプロンプト記録へ移動でき、リンク先が存在すること。
- 単発の記録や繰り返しを確認できない内容をknowledgeまたはruleへ昇格していないこと。
- knowledgeへの整理は、同じ分類または対象の2件以上の記録と、内容を比較して繰り返しを確認した根拠を示していること。
- ruleへの反映は、常時守らせたい意図の明示とその出典を示していること。
- 機密情報が通常の知識領域に転記されていないこと。
- 未検証事項、根拠不足、リンク切れを成功として扱わず、結果に明記していること。
