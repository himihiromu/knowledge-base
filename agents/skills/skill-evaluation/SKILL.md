# スキル評価

- 確認日: 2026-10-01
- 状態: 運用手順。採点は評価を実施するAIまたは人が行う。

## 目的

スキル修正の前後で、同じ入力・同じ評価基準で成果を比較できるようにする。
評価のたびに結果・採点理由・未検証範囲を記録し、修正の効果を後から確認できるようにする。

## 使う場面

- スキルを修正する前に、修正前の成果を評価して記録するとき。
- 修正後に同じケースで再評価し、差分を確認するとき。
- 対象スキルが未実装のときも、ケースに同梱した成果サンプルで評価経路を確認するとき（[example ケース](cases/example/case.md)）。

## 入力

評価のたびに次の3点を指定する。機構に固定値はなく、差し替えて使う。

| 入力 | 内容 | 例 |
| --- | --- | --- |
| 対象スキル | `agents/skills/<スキル名>/SKILL.md` のパス。未実装のときは「なし（成果サンプルを使う）」 | `agents/skills/knowledge-prompts/SKILL.md` |
| ケースID | `cases/` 配下のフォルダ名 | `example` |
| 版ラベル | 今回の成果に付ける自由記述のラベル | `修正前`、`v1` |

成果は対象スキルを実行して作る。対象スキルが存在しない場合は、ケース定義が示す成果サンプルを評価対象に読み替える。

## 手順

1. **ケースを読む**: `cases/<ケースID>/case.md` で入力・実行方法・評価基準を確認する。
2. **成果を用意する**: 対象スキルの SKILL.md の手順に従い、ケースの入力から成果を作る。対象スキルが存在しない場合は、ケース定義の成果サンプルを評価対象にする。
3. **記録する**: [result-template.md](result-template.md) を複製し、1回分の結果を記入する。判定に加え、評価基準ごとの採点理由と未検証範囲を必ず残す。必須項目を空欄のまま保存しない。
4. **保存する**: 出力先へ、ファイル名 `YYYY-MM-DD-<対象>-<版ラベル>.md` で保存する。`<対象>` は対象スキル名、成果サンプルで評価するときはケースID。同名ファイルが既にあるときは上書きせず、`-2`、`-3` のように末尾へ連番を付けた別ファイルにする。保存済みの結果ファイルは後から編集しない。比較は旧結果を読む側で行う。
5. **比較する**: 同じケースID・異なる版ラベルの結果が出力先にあれば、評価基準ごとの判定差分と採点理由の違いを読み、今回の結果ファイルの「比較対象の旧結果」「差分の要点」へ旧結果への相対リンクと差分を書く。比較対象がなければ「なし」とする。

## 出力先

[03-output/skill-evaluation/](../../../03-output/skill-evaluation/README.md) に結果ファイルを保存する。

## 確認方法

保存後に結果ファイルを開き、次を確認する。

- 必須項目（実行日、対象スキル、版ラベル、ケースID、使用した入力、結果、採点理由、未検証範囲、採点者）が空欄でない。
- 採点理由が評価基準ごとに書かれ、判定の根拠として読める。
- 未検証範囲に、今回確認できなかった条件とその理由が書かれている。
- 比較対象がある場合、「比較対象の旧結果」のリンクが解決し、基準ごとの差分が読める。

配置・言語・リンクの規約は[運用ルール](../../../00-rules/workflow.md)に従う。
