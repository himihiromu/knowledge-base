# technical-validation.md

## Scope

`ComparisonAsset` の設計について、以下を検証した。

- Remotion APIによるカードの順次表示
- フレームからの決定的な描画状態算出
- 2〜4件の件数制約と実行時検証
- 任意Propsとデフォルト値
- 画像指定方式
- 件数別Gridレイアウト
- 解像度、縦横比、文字量への耐性
- 描画処理と再計算コスト
- 既存Theme、画像Props、Scene形式との互換性

## Feasibility Assessment

実装可能と判定した。

確認済みのRemotion 4.0.484には、設計で利用する`AbsoluteFill`、`Sequence`、`useCurrentFrame`、`useVideoConfig`、`interpolate`、`Easing`、`Img`が存在する。

カード開始位置を`startFrame + index * cardStaggerFrames`とし、`Sequence`内のローカルフレームを補間することで順次表示を実現できる。補間範囲を`clamp`し、乱数、時刻、外部API、副作用、可変状態を使用しないため、同じProps、解像度、フレームから同じ描画結果を生成できる。

`Sequence`の既定ラッパーは絶対配置であるため、常設Grid itemの内側で`layout="none"`を指定する現行設計が必要である。画像の事前マウントも実現可能であり、`layout="none"`と`premountFor`を併用できない場合は、Sequenceを早期開始して論理開始フレームとの差を進捗計算から差し引く。

デフォルトの開始フレームは15、27、39、51、完成フレームは33、45、57、69となり、設計されたTimelineと整合している。

## Performance Concerns

最大4カードであり、フレームごとの処理は少数の`interpolate()`とスタイル値算出に限られる。複雑な演算、大量DOM、Canvas、フレーム依存URLは設計に含まれず、重大な性能懸念はない。

実装時には以下へ注意する。

- Theme、`labels`、`contentLimits`の解決結果を`useMemo()`で安定化する。
- 解像度依存のレイアウト値を不要に再計算しない。
- 毎フレーム新しいThemeオブジェクトを生成して`React.memo()`を無効化しない。
- 静的なカード本体と表示ブロックには`React.memo()`を適用できる。
- 画像には`Img`と事前マウントを使用する。
- 最大4件のため、単純な条件判定や小規模な配列走査まで過剰にメモ化しない。

対象解像度におけるbundle/render時間とメモリ使用量は実装前のため未確認である。実装後に2件、3件、4件、画像あり、最大文字量のサンプルで計測する必要がある。

## Type Design Review

`ComparisonItems`のreadonly tuple unionは、TypeScriptのリテラル入力を2〜4件に制約できる。公開型に`any`はなく、Variant、画像fit、枠線styleも文字列リテラルunionで制約されているため、型設計は妥当である。

tuple型だけではJavaScript、JSON、動的配列、型アサーション経由の入力を保証できないため、`unknown`を受ける実行時検証が必要である。検証ではルートだけでなく、各項目、`image`、`rating`、`animation`、Theme各カテゴリ、`labels`、`contentLimits`が適切なobjectまたはarrayであることを内部アクセス前に確認する。

以下の検証も必要である。

- 項目数が2〜4件であること
- `variant`と項目数が一致すること
- IDが空でなく、配列内で一意であること
- 必須タイトルが空でないこと
- 評価値が`0 <= value <= max`かつ`max > 0`であること
- フレーム値と表示上限が有限整数であること
- Theme数値が用途別の範囲内であること
- 最後のカードが`durationInFrames`内に完成すること

すべての検証通過後のみassertion functionで`ComparisonAssetProps`を保証し、検証前の`as ComparisonAssetProps`は使用しない。

## Props Review

`title`と`items`を必須とし、説明、画像、評価、メリット、デメリット、バッジを任意とする区分は要求と一致する。任意ブロックのwrapper自体を生成しないため、未指定時に不自然な空白を残さない。

以下のデフォルト値は計画と整合する。

- `variant: "auto"`
- `durationInFrames: 180`
- 開始15、間隔12、登場18フレーム
- `enterOffsetRatio: 0.04`
- `enterScale: 0.96`
- 画像fitは`cover`
- 画像positionは`50% 50%`

`labels`によりメリット／デメリット見出しを固定文字列にせず、`contentLimits`と`overflowIndicator`により長文の表示上限と省略規則を公開Propsとして指定できる。

Theme、`labels`、`contentLimits`はカテゴリごとのshallow mergeではなく、カテゴリ内の末端キー単位でデフォルト値へマージする必要がある。

空白だけの任意文字列は`trim().length === 0`を基準に非表示とする。画像の`alt`は装飾画像で空文字が意味を持つため、必須タイトルや`src`と同じ非空制約を課さない。

## Compatibility

確認済みの既存Themeは`backgroundStart`、`backgroundEnd`、`surface`、`border`、`text`、`textMuted`、`fonts.body`などを持つ。設計の`ComparisonTheme`は`background`、`cardBackground`、`cardText`、`typography.fontFamily`などを持つため、型とキー形式は一致しない。

既存Themeを`ComparisonTheme`へ直接渡すことはできない。独立したTheme Propsとして扱うか、既存Themeから変換するadapterを用意する必要がある。

既存画像Propsの`src?: string`と本設計の`image.src: string`は、URL文字列を`Img`へ渡す点で互換性がある。ローカル素材は呼び出し側で`staticFile()`によりURL化する。

既存Sceneは秒単位の`durationSec`、本Assetはフレーム単位の`durationInFrames`を使用するため、Sceneへ統合する場合はCompositionまたはadapter側でfpsを用いて変換する必要がある。

既存Asset export、Asset catalog、Asset専用Props規約は確認対象となる実装が存在せず、互換対象はない。

## Risks

- `Sequence`の既定レイアウトによってカードが重なる。
  - 常設Grid item内で`Sequence layout="none"`を使用する。
- 事前マウントの代替方式でカードが予定より早く登場する。
  - 早期開始分をローカルフレームから差し引く。
- 画像が表示開始時に未ロードとなる。
  - `Img`と事前マウントを使用する。
- 長文がカード外へ流出または無通知で欠落する。
  - line clamp、リスト件数上限、`overflowIndicator`を適用する。
- 縦長画面の3列表示で可読性が低下する。
  - 対応する最小解像度と最大文字量を定義し、実装後にレンダー確認する。
- Themeの負値や過大比率によって画面外配置が発生する。
  - 数値ごとの下限と上限を実行時検証する。
- 既存Themeとの直接互換を誤って宣言する。
  - 独立Themeまたはadapterとして明示する。
- AssetとCompositionの継続時間が一致しない。
  - 同じ`durationInFrames`値を共有する。
- リモート画像によってレンダー再現性が低下する。
  - 再現性が必要なサンプルではローカル素材と`staticFile()`を使用する。

## Recommendations

- 常設Grid item内で`Sequence layout="none"`を使用する。
- 事前マウント代替時は論理開始フレームとの差を補正する。
- tuple unionに加えて`unknown`からの全ネスト実行時検証を実装する。
- Theme、`labels`、`contentLimits`を末端キー単位でマージする。
- Theme数値へ用途に応じた上下限を設定する。
- 任意ブロックをwrapperごと省略する。
- 長文へline clamp、リスト件数上限、省略表示を適用する。
- 既存Themeは直接代入せず、独立Themeまたはadapterとして扱う。
- CompositionとAssetの`durationInFrames`に同じ値を使用する。
- 実装後に2件、3件、4件、任意項目省略、画像あり、最大文字量を型チェックと対象解像度のレンダーで確認する。
