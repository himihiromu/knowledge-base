# technical-validation.md

## Scope

`asset-design.md`を対象に、Remotion API、フレームベース描画の決定論性、自動スクロール、性能、TypeScript型、Props、Theme、既存コンポーネントとの互換性を検証した。

## Feasibility Assessment

条件付きで実現可能と判定した。

`useCurrentFrame()`、`useVideoConfig()`、`Sequence`、`AbsoluteFill`、`interpolate()`、`Easing`を用いる構成はRemotionのフレームベース描画に適合する。タイマー、乱数、DOM計測、React state更新を使わず、Propsと絶対フレームから表示状態を導出するため、同一入力・同一フレームでは同一結果になる。

固定行高と事前折り返しにより、スクロール量はDOM計測なしで算出できる。ただし`Sequence`内の`useCurrentFrame()`はローカルフレームになるため、Timeline計算では`ConsoleAsset`直下で取得した絶対フレームを使用する必要がある。

登場・退出を無効にした場合は実効継続時間を0とし、0フレームの`Sequence`を生成しない設計で実装できる。退出無効時は親Compositionまたは親Sequenceの終端まで表示する。

## Performance Concerns

折り返し処理、Timeline構築、Theme・寸法解決を毎フレーム再計算すると、長文や多数行で負荷が増加する。また、表示済み全行をDOMへ残す実装は、時間経過に伴ってDOM要素数が増える。

対策として以下が必要である。

- 折り返し済み行と各行の表示開始フレームを`useMemo()`で保持する。
- 表示済み末尾indexを二分探索で求める。
- 自動スクロール時はviewport周辺の行だけを描画する。
- `autoScroll=false`ではviewportに入る先頭側の行だけを描画する。
- 静的な行コンポーネントへ`React.memo()`を適用する。
- サンプルデータをコンポーネント外の定数として定義する。
- 実装後に1920×1080および多数行データでレンダリング性能を測定する。

実装前のため、具体的なベンチマーク値は未確認である。

## Type Design Review

判別可能Unionによる`ConsoleEvent`、文字列Unionによる出力種別・配置・Variant、`Readonly`の使用は妥当である。`any`を使用しない方針もstrict TypeScriptに適合する。

Theme上書き型には修正が必要である。現在の次の型では、`Partial<ConsoleTheme>`側に完全な`outputColors`型が残る。

```ts
Partial<ConsoleTheme> & Readonly<{
  outputColors?: Partial<ConsoleTheme['outputColors']>;
}>
```

次のように`outputColors`を一度除外してから部分型として追加する必要がある。

```ts
type ConsoleThemeOverrides = Readonly<
  Omit<Partial<ConsoleTheme>, 'outputColors'> & {
    outputColors?: Partial<ConsoleTheme['outputColors']>;
  }
>;
```

数値制約、重複id、割合寸法の妥当性はTypeScriptだけでは保証できないため、Runtime検証が必要である。特に、解決後の内容領域高が正数であることを検証しなければならない。

## Props Review

`events`だけを必須とし、速度、配置、Theme、アニメーションへ既定値を持たせる区分は妥当である。

優先順位も明確である。

- イベント固有`prompt`はトップレベル`prompt`より優先する。
- 明示`color`は出力種別のTheme色より優先する。
- 明示されたenter/exit設定はVariant既定値より優先する。
- 明示`startFrame`はAsset先頭基準であり、`playbackRate`では変換しない。

enter/exitオブジェクトはオブジェクト全体ではなくフィールド単位でマージする必要がある。例えば`enter={{enabled: false}}`でも、Variantの`durationInFrames`は保持する。

Runtimeでは、フレーム値、速度、寸法、列数、Theme数値、重複id、内容領域高を検証する必要がある。

## Compatibility

既存Themeは階層型の単一オブジェクトであり、設計された平坦な`ConsoleTheme`とは直接互換ではない。呼び出し側のadapterで以下を部分Themeへ変換すれば、既存Themeを変更せず利用できる。

- `backgroundColor` ← `theme.colors.surface`
- `textColor` ← `theme.colors.text`
- `promptColor` ← `theme.colors.terminalPrompt`
- `borderColor` ← `theme.colors.border`
- `fontFamily` ← `theme.fonts.body`または`monospace`

既存の`TerminalSceneView`はcommandとoutputを静的表示するため、新Assetと一部責務が重複する。既存データはcommandイベント1件と、必要に応じてoutputイベント1件へ変換できる。実装後はadapter経由で新Assetを利用し、コンソール描画を二重管理しない構成が望ましい。

サンプルCompositionは既存のComposition登録箇所へ固有idで追加する必要がある。公開Asset自体はComposition登録へ依存させない。

## Risks

- `Sequence`のローカルフレームを絶対Timelineへ使用すると表示時刻がずれる。
  - 対策: 絶対フレームをAsset直下で取得し、計算済み表示モデルを子へ渡す。
- Theme部分型のintersectionにより、出力色の部分上書きが型エラーになる可能性がある。
  - 対策: `Omit`を使用した上書き型へ変更する。
- 長大ログですべての表示済み行を走査・描画すると性能が低下する。
  - 対策: 前処理のmemo化、二分探索、viewport windowingを行う。
- 小さすぎる高さや過大なpaddingにより内容領域が0以下になる。
  - 対策: 解決後の内容領域高をRuntime検証する。
- 既存Terminal表示との重複実装が発生する。
  - 対策: 既存シーンデータから新イベント形式へのadapterを用意する。
- 依存パッケージのインストール済み型定義に対するコンパイル検証は未実施である。
  - 対策: 実装工程で`pnpm lint`を実行する。

## Recommendations

1. Theme上書き型を`Omit<Partial<ConsoleTheme>, 'outputColors'>`方式へ修正する。
2. Timeline計算にはAsset先頭基準の絶対フレームだけを使用する。
3. `Sequence`はマウント区間の表現に限定し、0フレーム区間を生成しない。
4. 折り返し済み行と開始フレームをmemo化する。
5. 表示済み末尾を二分探索し、表示行をwindowingする。
6. 内容領域高を含むRuntime入力検証を追加する。
7. 既存Themeと`TerminalSceneView`向けadapterを用意する。
8. 実装後に型チェック、決定論性確認、Timeline境界テスト、1920×1080での性能測定を行う。
