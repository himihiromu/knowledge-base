# technical-validation.md

## Scope

`asset-design.md`を対象に、以下を検証した。

- Remotion APIによるフレームベース描画の実現可能性
- 順次表示、自動スクロール、登場・退出の決定論性
- 長大ログに対する計算量とDOM描画量
- イベント、Theme、Variant、アニメーション設定の型安全性
- 必須・任意Propsとデフォルト値
- 既存Theme、TerminalScene、adapterとの互換性

## Feasibility Assessment

実現可能と判定した。

設計で使用する`AbsoluteFill`、`Easing`、`interpolate`、`Sequence`、`useCurrentFrame`、`useVideoConfig`は、導入済みの`remotion@4.0.484`で利用可能である。

絶対フレーム、正規化済みProps、Composition設定のみから表示文字数、出力行、スクロール位置、登場・退出値を導出するため、任意フレームの直接レンダーでも決定論性を維持できる。タイマー、乱数、DOM計測、外部I/O、Reactの可変stateは不要である。

補間範囲を`[startFrame, startFrame + durationInFrames - 1]`とし、duration 0ではSequenceを生成せず、duration 1では補間を行わず終端値を返す設計により、境界値も処理できる。

strict TypeScript検査は終了コード0で完了した。Studio再生および実レンダーは未確認である。

## Performance Concerns

Timeline構築、文字分割、折り返し、行開始フレーム、スクロール遷移をProps変更時に前処理し、フレームごとの処理を二分探索、定数回の補間、表示対象行の抽出に限定する方針は妥当である。

設計書には大量行表示時のDOM windowing範囲が明記されていない。全表示済み行を描画すると、ログの増加に比例してDOM数とReactの比較量が増える。

実装では、スクロール補間の始点offsetと終点offsetの小さい側から、大きい側にviewport内容高を加えた範囲までを描画し、上下1行をoverscanする必要がある。現在位置だけを基準にすると、補間中の行が欠ける可能性がある。

1920×1080、30fpsでの実レンダーベンチマークは未実施であり、レンダー速度の合否は未確認である。

## Type Design Review

型設計は妥当である。

- `ConsoleEvent`は`type`を判別子とするdiscriminated unionである。
- `ConsoleOutputKind`、`ConsolePosition`、`ConsoleVariant`は文字列unionで許可値を限定している。
- イベント、設定、配列は`Readonly`または`readonly`で定義されている。
- 解決済みThemeでは`Record<ConsoleOutputKind, string>`により全出力色が保証される。
- `ConsoleThemeOverrides`では`outputColors`をキー単位で部分上書きできる。
- 公開型と確認対象コードに`any`は使用されていない。

有限値、整数、正数、イベントIDの一意性はTypeScriptだけでは保証できないため、runtime検証が必要である。

`Array.from()`による分割はUnicode code point単位であり、結合文字やZWJ emojiのgrapheme clusterを途中で分割する可能性がある。

## Props Review

`events`のみを必須とし、その他へデフォルト値を設定する区分は妥当である。

イベント固有の`prompt`を共通`prompt`より優先し、outputの`color`を`kind`に対応するTheme色より優先する規則は明確である。

`playbackRate`の適用対象は文字間隔、行間隔、command後待機に限定され、登場、保持、退出、明示`startFrame`には適用されない。このため、内容表示速度を独立して調整できる。

`enter`、`exit`、`scrollAnimation`はフィールド単位でデフォルト値とマージできる。明示設定をVariant既定値より優先するため、登場と退出を個別に切り替えられる。

以下の境界条件も定義されている。

- 登場・退出が無効の場合は該当Sequenceを生成しない。
- duration 0では補間せず終端値を使用する。
- duration 1では唯一の描画フレームを終端値とする。
- `autoScroll=false`ではoffsetを0とする。
- スクロールアニメーション無効またはduration 0では即時移動する。
- 空の`events`ではContentSequenceを生成しない。
- 退出無効時はComposition終端まで最終状態を表示する。

## Compatibility

既存プロジェクトThemeと`ConsoleThemeOverrides`は直接同一形式ではないが、adapterで接続できる。

既存Themeの`colors.surface`、`colors.text`、`colors.terminalPrompt`、`colors.border`、`fonts.body`は、`projectThemeToConsoleTheme()`によってConsole Themeへ明示的に変換される。不足項目は`defaultConsoleTheme`で補完される。

既存`TerminalSceneView`の`command`と`output`は、`terminalSceneToConsoleEvents()`によって判別unionへ変換される。既存scene型を変更せずadapter境界で接続でき、型検査でも互換性が確認された。

## Risks

- 大量行をすべてDOM化するとレンダー負荷が増加する。
  - 対策: 補間始点・終点の両viewportを覆う行windowingとoverscanを実装する。
- スクロール補間中に次の行が追加されると、不適切な開始値計算で位置が跳ぶ可能性がある。
  - 対策: 境界フレームの補間値を次区間の開始offsetとして前処理する。
- Unicode結合文字が表示途中で分割される可能性がある。
  - 対策: READMEへ制約を記載し、必要に応じて決定論的なgrapheme単位分割へ拡張する。
- CSS色とshadowは文字列型であり、構文の正当性を型では保証できない。
  - 対策: ブラウザのCSS処理へ委ねる制約を文書化する。
- Studio再生と実レンダー性能は未確認である。
  - 対策: 実装後にサンプル再生と目標解像度でのベンチマークを実施する。

## Recommendations

- スクロール補間の始点・終点を覆う行windowingを実装する。
- 行keyをイベントID、論理行index、折り返し行indexから安定生成する。
- duration 0、1、12の登場・退出境界をテストする。
- `autoScroll=false`、スクロールアニメーション無効、duration 0をテストする。
- 補間中に次の行が追加されるケースをテストする。
- 同一Props、Composition設定、フレームの複数回描画が一致することを確認する。
- 1920×1080、30fpsで通常データと10,000表示行データをレンダーし、総時間、フレーム平均、最大同時DOM行数を記録する。
