# asset-design.md

## Component Overview

`ComparisonAsset` は、2〜4件の商品、サービス、方式、選択肢を1画面で比較表示する再利用可能な Remotion コンポーネントである。

比較件数に応じて左右2列、横3列、2×2グリッドへ自動的に切り替え、配列順にカードを段階表示する。各カードはタイトルを必須とし、説明、画像、評価値、メリット、デメリット、バッジを任意表示する。未指定の情報領域は描画せず、空白を予約しない。

レンダリング中の外部APIアクセス、ファイル読み込み、乱数、ユーザー操作、内部可変状態は使用しない。

## Composition

レンダリングツリーは次の構成とする。

```text
ComparisonAsset
├── ComparisonHeader
└── ComparisonGrid
    ├── AnimatedComparisonCard
    │   └── ComparisonCard
    │       ├── ComparisonCardHeader
    │       ├── ComparisonImageBlock（任意）
    │       ├── Description（任意）
    │       ├── ComparisonRatingBlock（任意）
    │       ├── ComparisonList: pros（任意）
    │       └── ComparisonList: cons（任意）
    └── ...2〜4件
```

各コンポーネントの責務は次のとおり。

- `ComparisonAsset`: デフォルト値、Theme、Variantの解決、入力検証、動画情報取得、全体配置。
- `ComparisonHeader`: 画面タイトルの表示と折り返し。
- `ComparisonGrid`: 件数別グリッドとカード順序。
- `AnimatedComparisonCard`: `Sequence` とフレーム値による登場状態の算出。
- `ComparisonCard`: 枠、背景、カード内の縦方向レイアウト。
- `ComparisonCardHeader`: 比較対象タイトルと任意バッジ。
- `ComparisonImageBlock`: `Img` による画像表示。
- `ComparisonRatingBlock`: 評価値と評価バー。
- `ComparisonList`: メリットまたはデメリットの見出しと一覧。

各子コンポーネントは単一責任とし、表示文字列、サイズ、色を内部へ固定しない。項目Props、解決済みTheme、`labels`、`contentLimits` を受け取って描画する。

## Animation Spec

使用する Remotion APIは次のとおり。

- `AbsoluteFill`: 全画面ルート。
- `Sequence`: カードごとの表示開始制御。
- `useCurrentFrame()`: カードのローカルフレーム取得。
- `useVideoConfig()`: 解像度とfpsの取得。
- `interpolate()`: 不透明度、移動量、拡大率の算出。
- `Easing.out(Easing.cubic)`: 登場終端の減速。
- `Img`: Remotion互換の画像表示。

カード `i` の論理上の開始フレームは次の式で決定する。

```ts
const start = startFrame + i * cardStaggerFrames;
```

登場進捗はカードのローカルフレームから算出する。

```ts
const progress = interpolate(frame, [0, cardDurationFrames], [0, 1], {
  extrapolateLeft: "clamp",
  extrapolateRight: "clamp",
  easing: Easing.out(Easing.cubic),
});
```

進捗に応じて次の値を補間する。

- `opacity`: 0から1。
- `translateY`: `enterOffsetRatio * availableGridHeight` から0。
- `scale`: `enterScale` から1。

指定フレーム数で確実に完了させるため、`spring()` ではなく `interpolate()` を使用する。

Grid itemは常設し、その内部の `Sequence` に `layout="none"` を指定する。画像は登場前から読み込みを開始できるよう事前マウントする。Remotionの型制約により `layout="none"` と `premountFor` を同時指定できない場合は、`Sequence` を早く開始して論理上の登場開始までは opacity 0を維持し、ローカルフレームを補正する。

## State

`useState`、Context、イベント状態などの内部可変状態は持たない。

描画結果は次の入力だけから決定する。

- Props。
- 解決済みTheme、labels、contentLimits。
- `useCurrentFrame()` の現在フレーム。
- `useVideoConfig()` の幅、高さ、fps。

状態遷移はカードごとの「未表示」「登場中」「表示完了」の3段階であり、現在フレームから直接導出する。Themeのマージ、Variant選択、レイアウト値、アニメーション進捗は純粋関数として算出し、同一入力と同一フレームから常に同一結果を生成する。

## Theme/Variant

Themeは末端キー単位で部分上書きし、指定されていない値にはデフォルトThemeを使用する。

デフォルトThemeは次の内容を持つ。

- 背景、タイトル、カード、補助文字、枠線、バッジ、評価、メリット、デメリットの色。
- 枠線幅2、スタイル `solid`。
- カード角丸18、バッジ角丸999、画像角丸12。
- 画面余白、タイトル間隔、グリッド間隔、カード余白、セクション間隔の相対値。
- フォント、タイトル・本文・補助文字の相対サイズ。
- 画像比率16:9、最大高比率0.24。

Variantは次のとおり。

| Variant | 件数 | 配置 |
| --- | ---: | --- |
| `auto` | 2〜4 | 件数から自動決定 |
| `two` | 2 | 1行2列 |
| `three` | 3 | 1行3列 |
| `four` | 4 | 2行2列 |

`auto` 以外のVariantと項目数が一致しない場合は実行時エラーとする。

## Layout

ルートは `AbsoluteFill` で Composition 全体を占有する。内部はタイトル行と比較グリッド行で構成する。

```text
grid-template-rows: auto minmax(0, 1fr)
```

件数別グリッドは次のとおり。

| 件数 | columns | rows | 表示順 |
| ---: | --- | --- | --- |
| 2 | `repeat(2, minmax(0, 1fr))` | 1行 | 左、右 |
| 3 | `repeat(3, minmax(0, 1fr))` | 1行 | 左、中央、右 |
| 4 | `repeat(2, minmax(0, 1fr))` | 2行 | 左上、右上、左下、右下 |

画面余白、間隔、カード余白、文字サイズは `min(width, height)` を基準とした相対値で算出する。画像最大高は利用可能なグリッド高を基準とする。

カードには `min-width: 0` と `min-height: 0` を設定する。カード内部は縦方向の通常フローとし、存在するセクションだけを生成する。任意項目がない場合はwrapper、gap、予約高を生成しない。

テキストは幅に応じて折り返し、`contentLimits` をCSS line-clampへ適用する。リストは `listItems` 件まで表示し、超過時は最後の表示項目へ `overflowIndicator` を付加する。カード本体は `overflow: hidden` とし、暗黙のスクロールは使用しない。

## Timeline

デフォルトは30fps基準、全180フレームである。フレーム区間は開始を含み、終了を含まない。

| 対象 | 2件 | 3件 | 4件 |
| --- | --- | --- | --- |
| タイトル | 0〜179 | 0〜179 | 0〜179 |
| カード1登場 | 15〜32 | 15〜32 | 15〜32 |
| カード2登場 | 27〜44 | 27〜44 | 27〜44 |
| カード3登場 | — | 39〜56 | 39〜56 |
| カード4登場 | — | — | 51〜68 |
| 全カード完成状態 | 45〜179 | 57〜179 | 69〜179 |

一般式は次のとおり。

- タイトル表示: `[0, durationInFrames)`。
- カード `i` の開始: `startFrame + i * cardStaggerFrames`。
- カード `i` の登場区間: `[開始, 開始 + cardDurationFrames)`。
- カード `i` の完成状態: `[開始 + cardDurationFrames, durationInFrames)`。
- 全カード完成開始: `startFrame + (items.length - 1) * cardStaggerFrames + cardDurationFrames`。

デフォルト30fpsでは、先頭カードは0.5秒後に開始し、カード間隔は0.4秒、登場時間は0.6秒、全体は6秒となる。fpsが異なってもPropsはフレーム値として扱い、秒数への自動変換は行わない。

## Constraints

- 比較項目数は2〜4件に限定する。
- TypeScriptではreadonly tuple unionで件数を制約し、実行時にも件数を検証する。
- Variantと件数の不一致を許容しない。
- `id` は空文字および重複を禁止する。
- 画面タイトルと各カードタイトルは空白文字のみを禁止する。
- `rating.max` は0より大きく、`value` は0以上かつ `max` 以下とする。
- フレーム値は有限整数とし、開始・間隔は0以上、アニメーション時間は1以上とする。
- `enterScale` は0より大きく1以下、`enterOffsetRatio` は0以上とする。
- `durationInFrames` は最後のカードの登場完了フレーム以上とする。
- 空の任意文字列および空配列は非表示として扱う。
- 画像は解決済みURLを受け取り、Asset内部でファイル読み込みを行わない。
- レンダリング中にAPI呼び出し、乱数、副作用を使用しない。
- 公開検証関数が `unknown` を `ComparisonAssetProps` へ絞り込む場合、ルートおよび全ネスト構造をアクセス前に検証する。
- `description`、`badge`、`pros`、`cons`、画像の各フィールド、評価ラベル、Theme文字列、labelsを指定時に検証する。
- `fit`、枠線style、Variantは定義済み文字列リテラルだけを許可する。
- `animation`、`theme`、`labels`、`contentLimits` に指定された非object値を未指定扱いにしない。
- Theme数値は有限値に加えて、余白、角丸、比率、行高、アスペクト比など用途別の上下限を検証する。
- `contentLimits` は1以上の有限整数とする。
- Assertion functionとして公開する場合、すべてのフィールドを検証した入力だけに公開型を保証する。
- 既存Theme型、Asset export規約、画像URL生成規約との互換性は、提供された設計資料だけでは未確認である。
