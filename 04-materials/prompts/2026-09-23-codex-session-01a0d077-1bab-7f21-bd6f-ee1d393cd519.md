# technical-validation.md

## Scope

`ComparisonAsset` の設計について、以下を検証した。

- Remotion APIによるカードの順次表示
- フレームからの決定的な描画状態算出
- 2〜4件の件数制約と実行時検証
- 任意Propsとデフォルト値
- 画像指定方式
- 件数別Gridレイアウト
- 解像度、縦横比、文字量への耐性
- 描画処理と再計算コスト
- 既存Theme、画像Props、Scene形式との互換性

## Feasibility Assessment

条件付きで実装可能と判定した。

プロジェクトで使用されているRemotion 4.0.484には、設計で利用する`AbsoluteFill`、`Sequence`、`useCurrentFrame`、`useVideoConfig`、`interpolate`、`Easing`、`Img`が存在する。

`Sequence`内の`useCurrentFrame()`はローカルフレームを返すため、カード開始位置を`startFrame + index * cardStaggerFrames`として順次表示できる。補間範囲の左右をclampすれば、同一Props、解像度、フレームから常に同一結果を得られる。

ただし、`Sequence`は既定で絶対配置ラッパーを生成する。CSS Grid直下でそのまま使用するとカードがGrid itemとして配置されず、重なる可能性がある。`layout="none"`を指定するか、常設Grid itemの内部に`Sequence layout="none"`を配置する必要がある。

画像を含むカードでは、表示前に読み込みを開始できるよう`premountFor`も指定する。

## Performance Concerns

カード数は最大4件であり、フレームごとの処理も少数の補間とスタイル算出に限られるため、設計上の重大な性能問題はない。

注意点は以下のとおり。

- Themeの末端マージを毎フレーム繰り返さない。
- 解像度依存のレイアウト値を不要に再計算しない。
- 毎フレーム新しいThemeオブジェクトを子へ渡して`React.memo()`を無効化しない。
- 静的なカード本体と表示ブロックには`React.memo()`を適用できる。
- Themeマージやレイアウト値は`useMemo()`で安定化できる。
- 小規模な文字列判定まで過剰にメモ化する必要はない。
- 画像にはRemotionの`Img`を使い、`Sequence`の`premountFor`で事前マウントする。

実装前の設計検証段階であるため、対象解像度における実測レンダリング性能は未確認である。実装後に2件、3件、4件、画像あり、最大文字量のサンプルで計測する必要がある。

## Type Design Review

`ComparisonItems`をreadonly tuple unionとして2件、3件、4件に限定する設計は妥当であり、`any`も含まれていない。

ただし、tuple型だけではJavaScript、JSON、動的配列、型アサーションを経由した入力を保証できない。実行時にも以下を検証する必要がある。

- 項目数が2〜4件であること
- `variant`と項目数が一致すること
- IDが空でなく、配列内で一意であること
- 必須タイトルが空でないこと
- 評価値が`0 <= value <= max`かつ`max > 0`であること
- フレーム値が有限整数であること
- アニメーション時間が1以上であること
- 最後のカードが全体終了前に完成すること

外部入力の検証関数は`unknown`を受け取り、型ガードまたはassertion functionで公開型へ絞り込むべきである。検証前の型アサーションは使用しない。

ネストした`Partial`によるTheme上書きは妥当だが、shallow mergeでは既定値が失われるため、カテゴリ単位で末端キーを明示的にマージする必要がある。

Theme数値は有限値の確認だけでは不十分である。負の余白、枠線、角丸、文字サイズなどを拒否し、`lineHeight`と画像アスペクト比は0より大きくする。画面余白率やその他の比率にも、画面外配置を防ぐ上限が必要である。

## Props Review

`title`と`items`を必須とし、説明、画像、評価、メリット、デメリット、バッジを任意とする区分は要求に一致する。

`variant: "auto"`、全体180フレーム、開始15フレーム、間隔12フレーム、登場18フレームというデフォルト値も計画と整合している。4件の場合も69フレームで全カードが完成する。

空の任意項目についてwrapper自体を生成しない設計は、不自然な予約領域を避けられる。空文字の判定は空白だけの文字列も含めて`trim()`基準に統一することを推奨する。

メリットとデメリットの見出し文言は現行Propsに含まれていない。画面へ表示する場合は固定文字列にせず、`labels`などの公開Propsを追加する必要がある。

`durationInFrames`は親Compositionの設定と二重管理になる。実装可能ではあるが、サンプルでは同じ定数を共有し、不一致を避ける必要がある。

画像の`src`を解決済みURL文字列として`Img`へ渡す方式はRemotionと互換性がある。ローカル素材は呼び出し側で`staticFile()`を通し、Asset内部でファイルパスを解決しない契約を明記する必要がある。リモートURLはレンダー環境のネットワークに依存するため、再現性が必要なサンプルでは使用しないことを推奨する。

## Compatibility

既存Themeと設計上の`ComparisonTheme`は型およびキー形式が一致しない。

既存Themeは`backgroundStart`、`backgroundEnd`、`surface`、`border`、`text`、`textMuted`、`fonts.body`などを持つ。一方、設計は`background`、`cardBackground`、`cardText`、`typography.fontFamily`などを定義している。このため、既存Themeをそのまま`ComparisonTheme`へ渡すことはできない。

互換対応として、次のいずれかが必要である。

1. 独立した`ComparisonTheme`を維持し、デフォルト値を既存Themeから対応付ける。
2. 既存Themeから`ComparisonTheme`へ変換するadapterを用意する。

既存の画像コンポーネントも`src?: string`を`Img`へ渡しており、画像URLのProps形式は互換性がある。

既存Sceneは継続時間に秒単位の`durationSec`を使用し、Assetはフレーム単位の`durationInFrames`を使用する。Sceneモデルへ統合する場合は、Compositionまたはadapter側で秒からフレームへ変換する必要がある。

既存のAsset export、Asset catalog、Asset専用Props規約は確認対象となる実装が存在しないため、互換性は未確認である。

## Risks

- `Sequence`の既定レイアウトによりカードが重なる。
  - `layout="none"`を必須にし、常設Grid item内で時間制御する。
- 画像が表示開始時点で未ロードになる。
  - `Img`と`premountFor`を使用する。
- 長文が`overflow: hidden`によって無通知で欠落する。
  - 行数、項目数、文字量の上限と省略方法を定義する。
- 極端な縦長画面で3列表示の可読性が低下する。
  - 対応する最小解像度、縦横比、最小文字サイズをREADMEに記載して検証する。
- Themeの負値や過大な比率により画面外配置が発生する。
  - 数値ごとの下限と上限を実行時検証する。
- 既存の暗色Themeと設計上の明色デフォルトThemeで外観が一致しない。
  - 既存Themeから既定色を対応付けるか、独立Themeであることを明示する。
- AssetとCompositionの継続時間が不一致になる。
  - 同じ定数を共有し、READMEに呼び出し側の責務を記載する。
- リモート画像によってレンダー再現性が低下する。
  - サンプルでは`public`配下の素材と`staticFile()`を使用する。

## Recommendations

- Grid内の`Sequence`に`layout="none"`を指定する。
- カード用Grid itemを常時配置し、その内部で登場状態を制御する。
- 画像カードの`Sequence`に`premountFor`を設定する。
- tuple unionに加えて`unknown`からの実行時入力検証を実装する。
- Theme数値へ意味に応じた上下限を設定する。
- Themeはカテゴリごとに末端マージする。
- ローカル画像は呼び出し側で`staticFile()`により解決する。
- 長文の表示上限、line clamp、省略記号、入力超過時の扱いを定義する。
- メリットとデメリットの見出しを表示する場合は公開`labels` Propsを追加する。
- 既存Themeとのadapterまたはデフォルト値の対応付けを実装する。
- CompositionとAssetの`durationInFrames`に共通定数を使用する。
- 実装後に2件、3件、4件、任意項目省略、画像あり、最大文字量のケースを型チェックおよび対象解像度でレンダー確認する。
