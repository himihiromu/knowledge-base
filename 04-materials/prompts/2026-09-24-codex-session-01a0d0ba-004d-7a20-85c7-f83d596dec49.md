# technical-validation.md

## Scope

`asset-design.md`を対象に、Remotion APIによる実現可能性、決定論的なTimelineと自動スクロール、長大ログ時の性能、TypeScript型安全性、Propsの必須・任意区分と既定値、既存Console Assetとの互換性を検証した。

Remotion依存を利用した型検査、Studio再生、実レンダーは未確認である。

## Feasibility Assessment

設計は条件付きで実現可能である。

- `useCurrentFrame()`と`useVideoConfig()`から表示状態を導出できる。
- `Sequence`で登場、内容、保持、退出を分離できる。
- `interpolate()`と`Easing`で登場、退出、スクロールをフレーム単位に補間できる。
- DOM計測やReact stateを使わず、Propsと絶対フレームから表示行とscroll offsetを決定できる。
- 折り返し行とスクロール境界を事前計算すれば、任意フレームの直接レンダーでも同一結果を得られる。

ただし、12フレームのSequenceが描画する範囲は0～11であるため、補間入力を`[0, 12]`にすると区間内で終端値へ到達しない。継続フレーム数を`d`とした場合、`d >= 2`では`[start, start + d - 1]`を使用し、`d <= 1`を個別処理する必要がある。

## Performance Concerns

Timeline構築、文字列分割、sort、スクロール境界計算をProps変更時だけメモ化し、各フレームでは二分探索と必要行の描画だけを行う構成が妥当である。

主な懸念は次のとおり。

- 全ログ行を毎フレーム走査または描画すると、長大ログで負荷が増える。
- 現在の目標offsetだけでwindowingすると、スクロール開始時に上端行が先にDOMから消える可能性がある。
- 純粋関数の計測結果だけでは、ReactおよびRemotionによる実レンダー性能を評価できない。
- 1920×1080での実レンダーベンチマークは未実施である。

補間前後のoffsetが覆う範囲を描画対象とし、上下1行をoverscanする必要がある。Timeline、Theme解決、スクロール境界は`useMemo()`で安定させ、行コンポーネントには`React.memo()`を適用する。

## Type Design Review

型設計は妥当である。

- `ConsoleEvent`は`type`を判別子とするdiscriminated unionである。
- 出力種別、配置、Variantは文字列unionで制限されている。
- イベントと設定はreadonlyであり、描画中の変更を防止できる。
- 解決済みThemeの`outputColors`は全出力種別を必須としている。
- `ConsoleThemeOverrides`は`outputColors`だけを部分型に置換しており、一部の色のみ安全に上書きできる。
- `any`は使用されていない。

有限値、整数、正数、一意なイベントIDなどはTypeScriptだけでは保証できないため、runtime検証が必要である。CSS色とshadowの構文は文字列型では保証されないため、制約をREADMEへ明記する必要がある。

## Props Review

`events`のみ必須とし、速度、寸法、配置、Theme、アニメーションへ既定値を設定する設計は妥当である。

- `playbackRate`は文字間隔、行間隔、command後待機へ一貫して適用される。
- `enter`、`exit`、`scrollAnimation`はフィールド単位で既定値とマージできる。
- 明示した登場・退出設定はVariant既定値より優先される。
- `autoScroll=false`ではoffset 0となる。
- scroll animationが無効または0フレームなら、目標位置へ即時移動する。
- `startFrame`をAsset先頭基準の絶対フレームとする規則が明確である。
- 空の`events`は空viewportとして扱えるため、禁止する必要はない。

フレーム値、interval、duration、寸法、Theme数値、`playbackRate`、`columns`にはruntime検証が必要である。

## Compatibility

確認された既存Console Assetのイベントunion、Theme、Theme上書き、配置、速度、登場・退出Propsは新設計と互換性がある。既存adapterもイベント配列とTheme上書きへ変換する形式であり、公開Propsを削除せず拡張できる。

後続実装では以下の差分反映が必要である。

- `ConsoleScrollAnimation`型を追加して公開する。
- `scrollAnimation` Propsを追加する。
- スクロール補間と補間対応windowingを実装する。
- 単一の全体Sequenceを区間別Sequenceへ変更する。
- README、サンプル、Catalog、既存adapterとの整合を更新する。

これらは追加変更であり、既存呼び出しは既定値によって維持できる。

## Risks

- 補間終端がSequence最終フレームと一致せず、区間切替時に表示が跳ぶ。
  - 対策: `duration - 1`を終端とし、0・1フレームを個別処理する。
- スクロール中にwindowing対象が先に切り替わり、行が瞬間的に消える。
  - 対策: 補間前後のviewport範囲とoverscanを描画する。
- スクロール中に次の行が追加されるとoffsetが不連続になる。
  - 対策: 境界フレームの補間値を次区間の開始offsetとして事前計算する。
- 多数行で全件走査や全DOM描画が発生する。
  - 対策: 前処理、二分探索、windowing、メモ化を使用する。
- Remotion型検査と実レンダー性能が未確認である。
  - 対策: 依存利用可能環境でLint、型検査、Studio確認、実レンダーを実施する。

## Recommendations

- 1フレームと12フレームの登場・退出について終端値をテストする。
- 区間別Sequenceに重複描画や空白フレームがないことを確認する。
- スクロール補間中の連続追加とwindowing境界をテストする。
- `static`、`animated`、enter/exitの4組、scroll無効、duration 0をサンプルで確認する。
- 同じPropsとフレームを複数回描画し、出力が一致することを確認する。
- 1920×1080、30fpsで通常データと多数行データを実レンダーし、所要時間を記録する。
- 公開型、README、サンプル、Catalog、adapterを同時に更新する。
