# technical-validation.md

## Scope

`asset-design.md` を対象に、以下を検証した。

- Remotion APIによるフレームベース描画の実現可能性
- 順次表示、自動スクロール、登場・退出の決定論性
- 長大ログに対する計算量とDOM描画量
- イベント、Theme、Variant、アニメーション設定の型安全性
- 必須・任意Propsとデフォルト値
- 既存コンポーネントおよびTheme形式との互換性

検証時点ではRemotion依存がインストールされておらず、型検査、Studio再生、実レンダーは未確認。

## Feasibility Assessment

条件付きで実現可能と判定した。

`useCurrentFrame()`、`useVideoConfig()`、`Sequence`、`AbsoluteFill`、`interpolate()`、`Easing`を用いる構成は、フレームベースの描画モデルと整合する。

絶対フレーム、正規化済みProps、Composition設定のみから表示文字数、出力行、スクロール位置、登場・退出値を導出するため、任意フレームの直接レンダーでも決定論性を維持できる。タイマー、乱数、DOM計測、外部I/O、Reactの可変stateは不要である。

補間終端を`durationInFrames - 1`とする規則により、Sequenceの最終描画フレームで終端値へ到達できる。duration 0、1およびアニメーション無効時の境界も定義されている。

## Performance Concerns

Timeline、文字分割、折り返し、スクロール境界をProps変更時に前処理し、現在フレームでは二分探索と補間だけを行う構成は妥当である。

一方、設計書には大量行表示時のDOM windowing範囲が明示されていない。全表示済み行を描画すると、ログ増加に比例してDOM数とReactの比較量が増える。

補間中は、`previousOffset`と`targetOffset`の小さい方から、大きい方に`contentHeight`を加えた範囲までを描画し、上下1行をoverscanする必要がある。現在のviewportだけを基準にすると、スクロール開始時に上端行が先に消える可能性がある。

1920×1080での実レンダーベンチマークは未実施。

## Type Design Review

型設計は妥当である。

- `ConsoleEvent`は`type`を判別子とするdiscriminated unionである。
- `ConsoleOutputKind`、`ConsolePosition`、`ConsoleVariant`は文字列unionで制約されている。
- イベント、設定、配列は`Readonly`または`readonly`で定義されている。
- 解決済みThemeでは`Record<ConsoleOutputKind, string>`により全出力色が保証される。
- `ConsoleThemeOverrides`は`outputColors`を部分上書きできる。
- `any`は使用されていない。

有限値、整数、正数、IDの一意性などはTypeScriptだけでは保証できないため、runtime検証が必要である。

`Array.from()`はUnicode code point単位であり、結合文字やZWJを含むgrapheme clusterの途中で折り返す可能性がある。この挙動は制約として明記する必要がある。

## Props Review

`events`のみを必須とし、その他にデフォルト値を設定する区分は妥当である。

`playbackRate`の適用対象が文字間隔、行間隔、command後待機に限定され、登場、保持、退出には適用されないため、速度調整の責務が明確である。

`enter`、`exit`、`scrollAnimation`はフィールド単位でデフォルト値とマージできる。Variantより明示設定を優先するため、登場と退出を独立して切り替えられる。

`autoScroll=false`、scroll animation無効、duration 0、空の`events`についても挙動が定義されている。

## Compatibility

既存構成に全Asset共通のTheme型またはProps型は確認されておらず、独自の`ConsoleTheme`と`ConsoleAssetProps`を導入しても規約上の衝突は確認されなかった。

既存Console Assetのイベントunion、Theme、Theme override、配置、速度、アニメーションの型形式は設計と一致する。任意Propsの追加は既存フィールドの削除や意味変更を伴わないため、後方互換性を維持できる。

Themeは完全な値へ解決してから子コンポーネントへ渡すため、子側が部分Themeを処理する必要はない。

## Risks

- Remotion依存が未インストールであり、APIの型検査と実レンダーは未確認。
  - 対策: 依存導入後にlint、TypeScript検査、Studio再生、実レンダーを実施する。
- 大量行をすべて描画するとDOM数が増大する。
  - 対策: 補間前後のviewportを覆うwindowingとoverscanを実装する。
- スクロール補間中に次の行が追加されると、不適切な開始値計算で位置が跳ぶ可能性がある。
  - 対策: 境界フレームの補間値を次区間の`previousOffset`として事前計算する。
- Unicode結合文字が見た目の途中で分割される可能性がある。
  - 対策: READMEへ制約を記載し、必要なら将来grapheme単位の分割へ拡張する。
- CSS色とshadowは文字列型のため構文を型で保証できない。
  - 対策: ブラウザのCSS処理に委ねる制約を文書化する。

## Recommendations

- 補間前後のviewportを覆う描画行windowingを実装する。
- 行keyをイベントID、論理行index、折り返し行indexから安定生成する。
- duration 0、1、12の登場・退出境界をテストする。
- scroll animation無効、duration 0、`autoScroll=false`をテストする。
- 同一Props、Composition設定、フレームの複数回レンダーが一致することを確認する。
- 1920×1080、30fpsで通常データと10,000行データをレンダーし、総時間、フレーム平均、最大同時DOM行数を記録する。
- 公開型、README、Catalog、既存adapterの整合性を実装後に確認する。
